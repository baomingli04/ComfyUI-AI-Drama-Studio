## 2026-09-28 追加：T11 音频剪辑（新需求，已答并已实现）

**需求**（用户原话）：左侧栏「测试」下面加一个音频剪辑项目，两个功能 —— 第一视频提取音频，第二音频编辑（提取音频中的几段音频，或合并这几段）。

**问与答：**

- **新-4 走不走 task 表？** → **不走**。本地 ffmpeg 同步处理，秒级返回；不落 task、不进 Comfy/LLM 队列，因此没有轮询、没有取消、没有日志弹窗。编辑状态（片段列表）只在前端内存里，**刷新即丢**，用户未要求保存，故不落库、不写 json。
- **新-5 ffmpeg 从哪来？** → 用户答复「你弄吧」，按推荐取**本机已有**的那份（零安装）：`D:\LiblibAI-workspace\comfyui-deploy-win\python_embeded\Lib\site-packages\imageio_ffmpeg\binaries\ffmpeg-win64-v4.2.2.exe`，写进 `settings.FFMPEG_EXE`。不 pip 装新包、不动系统 PATH。
  - 附带结论：imageio-ffmpeg **只带 ffmpeg、不带 ffprobe**，时长/采样率/声道改由 `ffmpeg -i` 的 stderr 解析。
- **新-6 前端怎么编辑？** → 波形/选区/试听/片段增删排序全在浏览器（canvas + Web Audio，**不引任何 npm 库**）；后端只做两件事：抽音轨、按片段列表渲染导出。
- **新-7 纯前端能不能不装东西做音频编辑？** → 选段/试听/合并导出 WAV 可以纯前端；但**视频提取音频必须有解码器**（Python 标准库无 mp4 解码），且浏览器不能编码 MP3，所以仍走后端 ffmpeg。

**实现落点**：见 `10-任务清单.md` E 节、`08` §2 例外说明、`04` 第 5 节页面清单。

## 2026-09-29 追加：T10 二采重绘页去掉「一采任务id」、补回上传（缺陷修复，已实现）

**需求**（用户原话）：「`/test/t10-repaint` 这个页面的 1 采任务 id 是什么，为什么会让填写 id，调查下，逻辑说不通」→ 调查后用户拍板「修复一下」。

**调查结论（修复前）：**「一采任务id」是**死字段**，且该页**提交必失败**。

- `task` 表没有「一采任务id」列（只有 `一采MP`/`二采MP`）。
- `接口/controllers/任务提交.py` 的字段白名单里没有它 → 前端传了也被**静默丢弃**，不报错。
- `能力/二采重绘.py` 只读 task 自己的 `正向提示词`/`输入视频1`/`输入图1..9`/`输入音频1..3`/`一采MP`/`二采MP`/`比例`/`视频时长`/`seed`。
- 工作流 `Minimax_H3二采重绘…json` **自含一采+二采**：`115 ResolutionSelector`(一采) → `302 MiniMaxH3ReferenceToVideo` 的 `width/height` + `309 ImageResizeKJv2`；`214 ResolutionSelector`(二采) → `213 ImageResizeKJv2`；源视频由 `144 VHS_LoadVideo` 吃 `输入视频1`（首帧→309→159→`ref_videos.ref_video_0`，音轨→`ref_video_audios` + 输出）。**一次运行跑完两档，不存在"另一个一采任务"可引用。**
- 该页**没有任何上传控件**，而 `能力/二采重绘.py` 有 `if not 任务.输入视频1: raise ValueError(...)` → 页面提交的任务必然报错。

**新-11 怎么修？** → 用户确认「按推荐的方案 2」：**去掉「一采任务id」输入框与必填校验，补回上传**，让页面给出工作流真正需要的东西。

| 源视频 | 必填，1 个，落 `输入视频1`（工作流 144 只有一个源视频槽） |
