## 1. 设计原则（已锁定）

1. **所有生成/测试任务只进一张 task 表管理。** 禁止再按测试类型各建一套「主执行表」。禁止一张旧式 `ComfyUITask` 用 category + JSON 参数垃圾桶。
2. **改表结构必须同步改本文。** 只改 SQL / models / 页面、不改本文 = 违规。先改文档，再出方案，确认后才动库。
3. **层级必须显式。** 第一版任务不挂项目（第一版没有项目表）。
4. **禁止两套平行宇宙。** 剧本线只按本文第 7 节建，禁止搬旧 django 的剧本表结构。
5. **禁止可空外键当常态。** 技能若已分类，分类外键必填；未分类用明确「未分类」分类行。
6. **状态用明确枚举，全库统一。** 含「已取消」。
7. **每个表必须能一句话说清：谁拥有它、它存在是为了什么、删主数据时它怎么处理。**
8. **字段先少后加。** 没有确认用途的字段不建。task 上已锁定的关键字段见 3.5，不得缺。
9. **每个功能字段必须有备注。** 文档「说明」列 = 建表时的 `COMMENT`。
10. **旧数据不迁。** 新库空库起步。
11. **发给 Comfy / LLM 的提示词按前端提交的完整文本落库。** 后端不再拼接后覆盖。正向、反向都在 task 表，页上能看见的就是库里的。
12. **ComfyUI 同时只能跑一个任务。** 已有一条 Comfy 任务处于「生成中」时，其它 Comfy 任务只能「排队中」，不得第二路同时 POST 开跑。
13. **输入硬上限：最多 9 张图、3 个视频、3 个音频。** 工作流 JSON 若更严，取更严的；JSON 更松也不能超过本上限。
14. **产物硬上限：一次任务返回 1 张图片，或 2 个视频，二选一。** 不得图+视频混返，不得超这个数。

### 3.5 task（唯一任务管理表）

一句话：**所有测试/生成任务（含 LLM 文本、识图、文生图、编辑、人物替换、首尾帧、参考生视频、去水印、二采）都提交到这一张表排队、执行、查询、取消。** 归属：创建它的用户。删除：直接删本行，无子表、无级联，不删用户。

表职责就是「任务管理」。前端任务列表、轮询、日志弹窗、取消，全部只认这张表的 id。

**Comfy 并发（已锁定）：** 任意时刻最多一条 Comfy 类任务处于「生成中」。其它已提交的 Comfy 任务必须是「排队中」，`开始时间` 为空，直到 Comfy 真正开始跑这一条才写入 `开始时间` 并改为「生成中」。

三个时间（已锁定，含义不许混）：

| 字段 | 含义 | 何时有值 |
|---|---|---|
| 创建时间 | 本平台收到提交、插入本行的时间 | 插入时立刻写 |
| 开始时间 | **ComfyUI 真正开始跑这个任务**的时间（进入 running，不是本平台创建，也不是还在 Comfy 队列里排队） | Comfy 开跑时写；排队中必须为空 |
| 结束时间 | 进入成功 / 失败 / 中断 / 已取消 的时间 | 终态时写 |

LLM 任务的「开始时间」= **向 LLM 发出请求的瞬间**（C10 已锁定）。LLM 也写开始/结束，但**不占用** Comfy 那一条「同时只跑一个」的名额。

| 产物视频2 | 字符串 512 | 可 | 成功时产出的第 2 个视频路径；仅一次返 2 个视频的任务填 |
| 错误信息 | 文本 | 可 | 失败、中断或取消时的异常信息 |
| 错误文件 | 字符串 512 | 可 | 失败时出错的 py 文件真实路径 |
| 错误行号 | 整数 | 可 | 失败时出错的行号 |
| 错误函数 | 字符串 100 | 可 | 失败时出错的函数名 |
| 创建时间 | 时间 | 否 | 任务在本平台创建的时间 |
| 开始时间 | 时间 | 可 | ComfyUI 真正开始跑该任务的时间；排队中必须为空 |
| 结束时间 | 时间 | 可 | 进入成功、失败、中断或已取消的时间 |

状态枚举（过程与结果分开）：

| 状态 | 含义 | 属于 |
|---|---|---|
| 已创建 | 库里有记录，还没提交到 Comfy / LLM | 过程 |
| 已提交 | 已拿到 comfy_prompt_id（LLM 则已发出请求） | 过程 |
| 排队中 | 在等待 Comfy；Comfy 正在跑别人的任务，或还在 Comfy queue pending | 过程 |
| 生成中 | **Comfy / LLM 正在跑这一条**（此时写入开始时间） | 过程 |
| 成功 | 已取回产物或 LLM 回复 | 结果 |
| 失败 | 明确失败，有错误行号 | 结果 |
| 中断 | 等待过程中连不上 / 超时 / 进程没了 | 结果 |
| 已取消 | 用户点了取消，不再继续等 | 结果 |

前端任务列表和日志弹窗必须能展示上述状态，以及创建时间 / 开始时间 / 结束时间。判断「生成中」必须用 Comfy queue running（或 LLM 请求进行中），禁止只看有没有产物文件，禁止用开始时间非空但 queue 已断来假装还在跑。

接口形态（已锁定）：提交后立刻插入 task 并返回任务 id；前端轮询详情；取消走单独路由，只取消这一条。

不放：JSON params、project_id、后端拼出来的提示词。不放去油腻勾选、工作流标识（本轮未点名，不加）。

**不再为每种测试建一对一参数表。** 正向/反向/尺寸/时长/seed/水印/系统提示词/一采MP/二采MP 都在 task 上。二采必须两列 MP，禁止一列「视频MP」兼存两个值。

### 3.6 输入与产物文件（task 列，禁止子表）

**已锁定（2026-09-18）：task 禁止任何子表。** 输入文件路径、产物文件路径全部直接落在 task 表的列上（见 3.5 表：输入图1…输入图9 / 输入视频1…输入视频3 / 输入音频1…输入音频3 / 产物图片 / 产物视频1 / 产物视频2）。不建「参考输入」「产物」子表，不用外键级联。

平台输入硬上限（已锁定，校验必须拒超）：

| 媒体 | 同一任务最多 |
|---|---|
| 图片 | 9 |
| 视频 | 3 |
| 音频 | 3 |

工作流 JSON 统计出的允许个数若更小，按 JSON；若更大，仍不超过上表。读不到 JSON 上限则停下来问，不许再放宽。

产物硬上限（已锁定）：

- **1~2 张图片**（产物图片 有值，需要两张时产物图片2 也有值），或
- **2 个视频**（产物视频1、产物视频2 有值）
- 二选一，不能同时有图又有视频，不能 3 张图，不能 3 个视频。LLM 正文写在 task.回复，不占产物名额。
- 两张图仅 `文生图8K`、`多图编辑多人合并版`、`三图编辑一致版` 使用，按 Comfy 返回文件名的放大标记分流：不带标记的是原图/成品（产物图片），带标记的是放大图（产物图片2）。`文生图8K` 用 `_4x`，多图/三图编辑用 `_hd`。

删除任务 = 直接删 task 这一行，无子表、无级联。
