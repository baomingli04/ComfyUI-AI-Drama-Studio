## 4. 启动前端

工作目录必须是 `frontend`。Vite 已锁 `server.port = 8080`、`server.host = '127.0.0.1'`。

### 4.1 开发（日常改页面）

首次或 `node_modules` 丢失时先装依赖：

```bat
cd /d D:\SC\web4\aicg\frontend
npm install
npm run dev
```

浏览器打开：`http://127.0.0.1:8080/`。

⚠️ **2026-10-20 实测：8080 被本机的 llama-server 占着**（跑的是 27B GGUF，很可能就是本项目
在模型配置页要填的那个 LLM）。Vite 端口被占时会**自动顺延**，实际起在 **`http://127.0.0.1:8081/`**。
别去杀 llama-server。若哪天 8080 空出来了，Vite 会自己回到 8080。

`package.json` 脚本：

| 命令 | 作用 |
|---|---|
| `npm run dev` | `vite`，开发服务 127.0.0.1:8080 |
| `npm run build` | `vite build`，产出 `frontend/dist/` |
| `npm run preview` | `vite preview`，本地预览构建结果 |

### 4.2 后端地址怎么配（开发、生产都看这个文件）

文件：`frontend/public/config.js`

```js
window.__APP_CONFIG__ = { 后端: "127.0.0.1:8001" };
```

规则（已锁定，不要改格式）：

- 只写 `主机:端口`
- **禁止**写 `http://` / `https://`
- 前端用当前页协议拼接，例如登录页：`window.location.protocol + '//' + 后端 + '/api/登录'`
- `index.html` 在 `<head>` 里先加载 `/config.js`，再进 `/src/main.js`
- 构建时 Vite 会把 `public/config.js` 原样拷到 `dist/config.js`。生产换后端地址，改这一处再重新 `npm run build`（或直接改已部署的 `dist/config.js`，不必为改地址重编业务 JS）

当前引用 `window.__APP_CONFIG__` 的位置：`src/接口/请求.js`、`src/views/登录/index.js`、`src/views/技能管理/确认分类弹窗/index.js`、`src/views/工作流下载/index.js`。

开发默认前后端都在本机：前端 8080，后端 8001。规范约定 **dev/prod 默认都是 `127.0.0.1:8001`**，除非生产机器上后端真换了主机或端口。

### 4.3 本机构建预览（不是生产部署）

```bat
cd /d D:\SC\web4\aicg\frontend
npm run build
npm run preview
```

规范：**生产也不把 `dist` 塞进 Django 托管。** 前端静态和后端 API 始终分端口 / 分服务。

## 5. 迁移生产环境

前提：生产仍是本机或局域网管理员平台，不是公网开放注册站。旧数据不迁。端口能继续用 8001 / 独立静态端口就不要改口。

### 5.1 必须改的文件

| 文件 | 改什么 | 现在的值 | 生产要改成 |
|---|---|---|---|
| `backend/后端/settings.py` | `DEBUG` | `True` | **`False`** |
| `backend/后端/settings.py` | `ALLOWED_HOSTS` | `['127.0.0.1', 'localhost']` | 加上生产实际访问的主机名 / IP。只用 127.0.0.1 就不用扩 |
| `backend/后端/settings.py` | `SECRET_KEY` | 仓库里写死的字符串 | 生产换成独立密钥，不要继续用仓库那串 |
| `backend/后端/settings.py` | `DATABASES` | `127.0.0.1` / `root` / `root` / `aicg` / `3306` | 仅当生产 MySQL 不在本机、或账号不是 root/root 时才改。改完仍须 utf8mb4 |
| `frontend/public/config.js` | `后端` | `"127.0.0.1:8001"` | **仅当生产后端主机或端口变了才改**。仍只写 `主机:端口`，禁止加 `http://`。没变就不动 |
| `backend/后端/settings.py` | `FFMPEG_EXE` | 指向本机 ComfyUI 环境那份 ffmpeg（`D:\ComfyUI-aki-v3\python\Lib\site-packages\imageio_ffmpeg\binaries\ffmpeg-win-x86_64-v7.1.exe`，2026-10-20 从已失效的 `D:\LiblibAI-workspace\...` 改过来） | 生产机器上若没有同一路径，改成该机实际 ffmpeg 路径（T11 音频剪辑要用） |

可选、未在规范里锁死、迁之前要先问你再动：

- `CORS_ALLOW_ALL_ORIGINS = True`：开发全开。生产若只给固定前端源，再改成白名单。本文不擅自改代码。
- `frontend/vite.config.js`：当前只有 dev `server` 和 `@` 别名，没有 `base`。如果静态站点不挂在域名根路径，再补 `base`。挂在根路径就不用改。

**不要改：** `vite.config.js` 的前端开发端口 8080、aicg 后端端口 8001（除非你明确改口）。不要去动 `D:\SC\web4\django`。

## 6. 打开调试浏览器（看 xjf.cool 画面时用）

用途只有一个：**写前端画面时**，开一个**你本机真实身份**的可见 Chrome，你登录后 AI 通过 CDP 读页面实现。流程见 `docs/12-前端页面设计任务流程.md`。

### 6.1 一次性准备：建目录联接

Chrome 有硬性限制：`DevTools remote debugging requires a non-default data directory`——**默认 profile 一律禁止开远程调试端口**。

绕法：建一个指向真实 profile 的**目录联接**，从这个新路径启动。既是真实身份（同一份 Cookies / 登录态），又能拿到 CDP，**不复制任何数据**（profile 有 800MB+，复制既慢又没必要）。

PowerShell 执行一次即可：

```powershell
New-Item -ItemType Junction -Path D:\SC\web4\chrome-identity -Target "C:\Users\Administrator\AppData\Local\Google\Chrome\User Data"
```

### 6.2 每次启动

**先关掉所有已运行的 Chrome**（否则新启动会委托给旧实例，调试端口不会监听）：

```bash
MSYS_NO_PATHCONV=1 taskkill /IM chrome.exe /F
```

（`MSYS_NO_PATHCONV=1` 必须加，Git Bash 会把 `/IM` 当路径转义掉。）

再启动，端口固定 **9223**：

```bash
"/c/Program Files/Google/Chrome/Application/chrome.exe" \
  --remote-debugging-port=9223 \
  --remote-allow-origins=* \
  --user-data-dir="D:/SC/web4/chrome-identity" \
  "https://xjf.cool/workshop"
```

验证：

```bash
curl --noproxy '*' -s http://127.0.0.1:9223/json/version   # 应返回 Chrome/x.x
curl --noproxy '*' -s http://127.0.0.1:9223/json/list     # 应列出标签页
```

### 6.3 三个坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 9223 不监听 | 已有 Chrome 占着 profile，新进程委托给它 | 先 `taskkill`，再启动 |
| 启动命令立刻失效、进程消失 | 普通 Bash 调用结束会杀掉子进程 | 必须用**后台任务**方式启动 |
| `curl 127.0.0.1` 不通 | 本机有代理环境变量 | 加 `--noproxy '*'`；Python 侧用 `ProxyHandler({})` |

### 6.4 纪律

- 端口只用 **9223**，不用 9222（9222 是 Playwright 默认端口，会抢）
- **不复制 profile**，只用联接
- 启动后**由用户登录**，AI 不碰账号密码、不过验证码
- 登录是会话 cookie，浏览器关掉就没了，重启后要重新登录
- 同时只能跑这一个实例

## 8. 本机踩过的坑（2026-10-20 重建环境时实测）

### 8.1 建完 venv 千万别 `pip install --upgrade pip`

现象：pip 整个消失，后续命令报 `No module named pip`，还伴有
`Ignoring invalid distribution ~ip (...\.venv\Lib\site-packages)`。

原因：pip 自升级同样是「先卸载旧 pip 再装新的」，卸载步骤被本机沙箱的删除守卫接管，
旧 pip 目录被**改名**成 `~ip`、`~ip-24.0.dist-info` 留在原地，新 pip 又没装上。

修复（不用重装 venv）：

```bat
cd /d D:\视频图片素材\aicg\backend\.venv\Lib\site-packages
rename ~ip pip
rename ~ip-24.0.dist-info pip-24.0.dist-info
```

预防：新建 venv 后直接 `pip install -r requirements.txt`，**跳过升 pip**。
venv 自带的 pip 24.0 完全够用，那个升级提示忽略即可。

### 8.2 后端起不来先查两件事

1. **`manage.py` 里有启动互斥**：8001 已被占用会直接拒绝启动并打印占用者 PID。
   这是刻意设计（防止多个执行器抢同一条任务重复提交 ComfyUI），不要绕过它。
2. **连不上 3306** 就是数据库进程没起（MariaDB 没注册成服务，见第 2.0 节），
   不是代码问题。

### 8.3 前端端口不是 8080

8080 被 llama-server 占着，Vite 会顺延到 8081。见第 4.1 节。

### 8.4 任务建了但不动：执行器线程被 MySQL wait_timeout 悄悄杀死（2026-10-21）

**现象**：前端提交任务成功、`task` 表有记录，但状态永远停在「已创建」，
`comfy_prompt_id` / `开始时间` 为空，`资源/日志/` 下也没有 `task_<id>.log`。
表现为「任务创建了但没有跑」。

**根因**：执行器（`能力/提交并等待.py` 的 `_comfy线程` / `_llm线程`）是 Django
进程内的常驻线程，循环里 `_取最旧已创建()` 这句数据库查询**在 try 之外**。
线程的 DB 连接空闲超过 MySQL `wait_timeout`（默认 28800 秒 = 8 小时）被服务端
掐断后，下一次查询抛 `OperationalError(2006, 'MySQL server has gone away')`，
无人捕获 → 整个执行器线程静默退出。之后所有新任务都卡在「已创建」。
（HTTP 接口不受影响：Django 默认 `CONN_MAX_AGE=0`，每个请求独立建连，所以照常能写库。
隔夜无人用之后第一个任务必中此招。）

**判断方法**：`task` 状态 = 已创建、没有 `task_<id>.log`，而 3306 / 8001 端口都正常
→ 就是执行器线程死了，**重启后端即可**（`ready()` 会重新拉起两个线程，
重启后卡住的任务会被自动捡起继续跑）。

**已修**（2026-10-21，`能力/提交并等待.py`）：

- 新增 `_线程取任务()`：查询失败时 `connection.close()` 丢掉坏连接、睡 5 秒重试，绝不让线程退出；
- 两个线程的循环体整体加兜底 `try`，漏网异常仍按原语义「标失败 + 继续」；
- 等待循环里查取消状态的那句查询改软失败（查询异常时当 None，不拖垮正在跑的任务）。
