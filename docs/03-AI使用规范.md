# AI 使用规范

本文件约束所有在本仓库里动手的 AI（含后续会话）。违反即停工，不得用「顺便」「更完整」「行业惯例」辩解。

## 1. 范围铁律

1. **只做用户这一句要求的事。** 不得自行扩大到相邻功能、相邻文件、相邻表。
2. **禁止「直接写一个范围出来然后开工」。** 没有用户点名的模块，文档里可以列为待确认，代码里不许出现。
3. **禁止自作主张加逻辑。** 包括但不限于：跳过行、错误兜底分支、派生业务键、额外校验、额外字段、额外页面、额外依赖。需要加必须先问。
4. **「给例子 / 能调用」≠ 授权改业务代码。** 只允许写独立示例文件；改不改原项目由用户决定。
5. **选项式提问 ≠ 授权改用户源文件。** 用户没说「按这个改 / 就这样写」，不许覆盖。
6. **禁止照抄旧 django 的测试页、Comfy 等待、库表，禁止迁旧数据。** 可以读，不能搬。
7. **禁止一个 vue 塞多个功能。** 一个功能一个页面目录。二采不得塞进参考生视频页。
8. **写 py 之前库表必须已在 `02` 定稿。** 禁止先抄旧脚本再补列。
9. **新写的能力函数必须能被任何地方用同一入口调用。** 禁止测试专用一份、生产再写一份。
10. **不要 TS。** 不要 ViewSet。不要把 dist 塞进 Django（始终分端口）。
11. **每个库字段必须有备注。** 文档无说明的列不许建。**改表结构必须先改 `02-数据库文档.md`。**
12. **禁止后端拼接提示词。** 发给 Comfy / LLM 的文本必须等于前端提交、页上能看见的那一份。
    - **边界（不是例外）**：本条只约束**本后端 Django 代码**。链路下游由 ComfyUI 做的加工——Director 补 `<Picture i>` 标签 / fl2v 中文锁定包裹 / 官方 tokenizer 按 presentation 拼 `<Picture i>: ` + 视觉块——不在本条约束内，也禁止不了（那是官方节点行为）。详见 `14-两套方案对照（待实测选型）.md` §4。
13. **禁止在 `config.js` 的地址里写 `http://` 或 `https://`。**
14. **改库先给 SQL 文本，确认后再执行。** 包括插入管理员 `zhsw`。禁止 AI 自己连 MySQL 先插。
15. **测试上传平台上限 9 图 / 3 视频 / 3 音频。** 工作流 JSON 更严则取更严。读不到 JSON 上限就问，不许放宽、不许另定 N。
16. **现在不要去登录 https://xjf.cool/workshop。** 写前端画面时再开调试浏览器，等用户登录后看实现。前端拆分只学 kbhb；画面气质只学 copyweb/xjf，禁止把 copyweb 的 Vue3+Tailwind 当本项目写法。**全站必须深色科技感、必须套公共 `views/壳/`。** 禁止每页自己写壳，禁止混用浅色。色板以 `06` 2.1 为准，不许另起一套。壳里导航已锁定：左侧栏（深色 el-aside + el-menu，见 `07` G1）。
17. **所有任务只进一张 task 表。** 禁止再为每种测试建主执行表。Comfy 同时只跑一条。开始时间 = Comfy 真正开跑。
18. **产物最多 1 图或 2 视频。**
19. **第一版测试列必须有：** seed、水印、系统提示词、一采MP、二采MP。禁止用一列「视频MP」兼存两个值。用户表按 `02` 3.1。
    - **视频画布的用户输入口径是「比例 + MP」，不是手填宽高。** `视频宽`/`视频高` 由这两者算出（32 倍数）后回填落库，页面上**只读显示**；任何页面不许再给宽/高输入框让用户手填。见 `14` §3（P2 已定方案 B）。

## 2. 方案先行

任何开发（含建目录骨架、装依赖、建表、写第一个接口、写第一个页面）之前：

1. 先出**书面方案**：要动哪些路径、做哪些接口/页面/表、明确**不做**什么。
2. 等用户确认方案。
3. 确认后的方案在执行中如果和现场不一致，**必须停下提问**，得到认可再继续。
4. 不得用「先写一版你再看」跳过确认。

方案最小结构：

- 目标（一句话）
- 范围内文件/接口/表清单
- 范围外（本次绝不碰）
- 与已确认规范的对照（一功能一页、共用日志弹窗、vue 拆分、一路由一方法、try、真实路径行号、py 可复用、等待契约、config.js 无协议、无 TS、MySQL COMMENT、完整提示词前端提交、取消任务、改表必改 02、task 单表、9/3/3、1图或2视频、Comfy 同时一条）
- 有歧义的点（列出来问，不许自行拍板）

## 3. 提问纪律

- 拿不准就问，问具体选项或具体字段，不要丢一堆链接冒充讨论。
- 用户已经否定的技术路径，立刻放弃，不许换说法再推一次。
- 用户说界面没有某字段，相信用户，不要再让他填那个框。
- 用户给过的信息不要再重复索要；本会话确实没留住时，只说「没留住，请再发一次」。
- 用户已说「旧数据肯定不要迁」，以后禁止再问要不要迁、禁止提议 dump 旧库。
- 用户已指定管理员账号密码、MySQL root/root，以后禁止再问「管理员怎么来」「库连哪」。

## 4. 改代码时的交付方式

- 改已有项目：先找同类实现，按现有写法套。本仓库标准是 kbhb 拆分 + 本文档，不是旧 django 仓后来的写法。画面可对 copyweb 预览和 xjf.cool，但拆分纪律仍是 kbhb。
- 给修改时给**整段可替换代码**，不要只丢逐行 diff 让用户自己拼。
- 只改被点名的片段。
- 汇报改动必须用真实时间戳和文件列表。
