## 3. 统一返回（已定稿，字段名按 07 D3）

提交接口（立刻返回，不等待终态）：

```text
ok: true
任务id: 整数
```

轮询详情：

```text
ok: true
任务id
状态
正向提示词
反向提示词
图片宽 / 图片高
视频宽 / 视频高 / 一采MP / 二采MP / 生成时长
seed / 水印 / 系统提示词
创建时间 / 开始时间 / 结束时间
产物图片 / 产物图片2 / 产物视频1 / 产物视频2   # task 列，最多 2 图（仅文生图8K、多图编辑多人合并版、三图编辑一致版）或 2 视频，图片与视频互斥
错误字段（若失败）
```

失败：

```text
ok: false
error: 异常类型 + 信息
file: 出错文件真实路径（生产同样给真实路径）
line: 出错行号
func: 出错函数
任务id: 若已建记录则给
```

取消接口：

```text
ok: true
任务id
状态: 已取消
```

已锁定：**路由提交后建 task 并启动执行；接口立刻返回任务 id；前端轮询任务详情；日志弹窗按任务 id 拉日志；取消是独立路由。** 禁止改回「接口阻塞到成功或失败再返回」。

## 4. 等待协议（必须重写，禁止搬旧 wait）

等待模块只根据 Comfy / LLM 真实接口更新 `task.状态` 和三个时间，并往本次日志文件追加行。LLM 文本/识图同样写日志文件。

**Comfy 同时只能跑一个任务。** 调度原则：

- 已有 task 状态=生成中（Comfy 类）时，新提交的 Comfy 任务只能是排队中，`开始时间` 保持空。
- 当前这条离开生成中（成功/失败/中断/已取消）后，才允许下一条从排队中进入生成中，此时才写 `开始时间`。
- 开始时间 = Comfy queue 显示该 prompt_id 为 running 的时刻，不是本平台 INSERT 的时刻，也不是 POST /prompt 的时刻。

必须能区分：

| 现象 | 状态 | 怎么判断（原则，实现方案确认后再写） |
|---|---|---|
| 已插入 task | 已创建 | INSERT |
| 已 POST /prompt 且拿到 id | 已提交 | 响应里的 prompt_id；此时若 Comfy 正忙则转为排队中 |
| 等别人跑完，或自己在 queue pending | 排队中 | 本平台队列 + Comfy queue；开始时间必须空 |
| 自己在 queue running | 生成中 | queue 接口；**此刻写开始时间** |
| history 成功且有输出 | 成功 | history；再拷文件到 `backend/资源/产物/`、把路径写进 task 产物列（1 图或 2 视频）；写结束时间 |
| history 明确 error | 失败 | history / 节点 error；写结束时间 |
| 连不上 Comfy / LLM | 中断 | 探活失败，**不是**继续显示生成中；写结束时间 |
| 超过约定超时仍无终态 | 中断 | 超时时钟，需你定秒数 |
| 用户点取消 | 已取消 | 取消接口把任务标已取消、写结束时间；对 Comfy 再尝试 interrupt（方案确认后写细节） |
| 只有输出目录多了文件 | **不能**单独用来判断进行中 | 文件是结果信号，不是过程信号 |

禁止：

- 用「task 产物列非空」判断正在生成。
- 用「创建时间」冒充开始时间。
- 用假睡眠代替轮询。
- 同时让两条 Comfy 任务进入生成中。
- 把 VRAM 猜测、旧 running_stuck_limit=1500 原样搬过来。若要卡住检测，单独出方案。
- wait 内部吞掉异常只返回空文件列表。
- 后端拼接提示词。
- 产物超过 1 图或 2 视频仍当成功写入 task。
- 输入超过 9 图 / 3 视频 / 3 音频仍提交。

日志：每次状态变化、每次排队位置、开始时间写入、每次失败、取消，写进该任务的日志文件（`backend/资源/日志/`）。前端不自己拼过程，只展示这份日志。

## 6. 技能包

- 来源两种：① 上传压缩包（zip 等），后端解压到 `backend/资源/技能/<目录名>/`（`来源=上传压缩包`）；② 直接放进该目录后登记（`来源=本地导入`），目录须自带 `SKILL.md`。
- 删除技能：删表行，并删除对应磁盘目录。
- 两种来源都**不扫描磁盘自动建行**。

## 7. 调用方纪律

- 路由函数：try 包住；只组参数、调「创建 task+触发执行」或取消入口；把统一返回交给前端。
- `执行xxx`：校验本类型参数和 9/3/3、落 task（输入文件路径写入 task 输入列：输入图1…9 / 输入视频1…3 / 输入音频1…3）、准备输入文件、把前端给的完整正向/反向原样写入 task 并送给模型。
- 「提交并等待」：不看业务类型，只看工作流 JSON + prompt_id；维护「同时只跑一条」；必须能被取消打断；开始时间只在真正 running 时写。
- 其它地方以后要生图：import 同一 `执行文生图`，不得复制一份改名。
- 改 task 字段 / 状态机：先改 `02`，再改本文，再改代码。
