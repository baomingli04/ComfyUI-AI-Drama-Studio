# 分镜规则（参考文档）

> 本文件是**功能 4（剧本 → 分镜）**的单一可信源。它定义两件事：
> 1. **过程**：怎么把功能 3 的导演剧本切成可执行分镜；
> 2. **输出**：每段分镜落盘成什么样（`提示词生成.md` 分镜 md）——其中明确每段「资产用什么工作流 / 工作流提示词 / 背景是什么的提示词」。
>
> 切镜手艺为本技能自有（通用切镜原则整理）；导演连贯（朝向 / 背景 / 声音 / 转场）见下方「硬规则」第 7/8/9 条；H3 提示词格式（FL2VA 单行 / Ref2VA 六段式）与图片 / Qwen 首帧提示词见下方「工作流提示词写法」；执行阶段的出图 / 出视频路由详见 `首尾帧生成规则.md`（功能 5）/ `分镜转视频.md`（功能 6）。

## 何时读 / 读它干什么 / 不读会漏什么

- **何时读**：功能 4 调用时——已拿到功能 3 的导演剧本（含世界书），要拆成可执行的电影分镜。
- **读它干什么**：按本规范先把剧本切成「事件链 / 节拍表」，再逐段填齐 `提示词生成.md` 的全部字段（角色 / 两段工作流 / 首尾帧 / 背景 / 时长 / 声音 / 图片正反向提示词 / 视频提示词 / 连续性锚点 / 转场 / 对话）。
- **不读会漏什么**：字段填不全 → 出图 / 出视频时 AI 自由发挥，人物漂移、背景乱换、时长超限、首尾帧缺失导致动作不连贯；提示词格式错 → FL2VA/Ref2VA 跑不通或串脸。

## 硬规则（红线）

1. **单段时长 ≤ 14 秒**：超过则必须再拆段。海螺 / 多数视频模型的单段上限即 14 秒。
2. **每段是一个独立镜头块**，块内字段必须全部填齐，缺一项不许开工。
3. **角色必须来自 `角色背景一览表.md` 的「剧情角色清单」**，剧情角色清单的对应角色用参考图文件名锚定，禁止凭空捏角色。
4. **背景必须指定背景目录里的某张图，或剧本中明确写出的文字描述背景**，禁止「随机背景」；与剧本场景一致（见规则 7）。
5. **主渲染工作流二选一**：每段分镜的「主渲染工作流」只从两个视频工作流（视频-首尾帧 / 视频-多参考）选其一，不得混用，决策理由写进字段；「文生图」「图片工作流」为**资产预备**（出背景图 / 出首尾帧图），按需使用、不与主渲染混选。
6. **首尾帧决策必须显式写明「是 / 否」并给原因**。
7. **背景锁定**：同一 `场景ID` 的各段，**背景描述字符串逐字一致、背景图同一文件**，禁止偷偷换背景或改写背景词；场景ID 变化（故事环境真变）才允许不同。
8. **朝向**：多人段每个出场角色都必须写明朝向（面向镜头 / 背对 / 侧脸 / 低头 / 转头 / 看向某角色互看）；对话段双方面向对方，禁止留空让模型默认全看镜头。
9. **声音**：有对白的段必须计划「清晰中文配音 + 中文字幕」；无人说话的段，**不写环境声、不写实 BGM**，`overall_soundscape` 写「无环境声」或仅必要的**关键动作声**（如武器挥击 / 拳脚击打 / 摔落），并标注「全程无人物发声」抑制 H3 自发含混人声；`overall_soundscape` **绝对禁止**写人声类词（低语 / 喊声 / 交谈声等）。

## 工作流选择（四类，按需选用）

| 工作流（中文名） | 底层技术 | 作用（输入 → 输出） | 何时用 |
|---|---|---|---|
| 文生图工作流 | Z-Image（纯文生图） | 纯文本提示词 → 静帧图（无需参考图，从零出图） | **仅用于「无现有背景资产」时生成背景 / 概念图**：凭剧本背景提示词 + `世界书.md` 基调直接出图，提示词必须含「无阴影、无暗影」以保证背景一致；已有背景图则不出图、直接复用。人物 / 首帧一律不走文生图（人物一致性靠参考图，走图片工作流）。 |
| 图片工作流 | Qwen 图像编辑 | 参考图（最多 3 张，典型 1 背景 + 2 人物）+ 提示词 → 编辑出的静帧图（换衣 / 换脸 / 改局部 / 多人同框合成） | **资产预备：产出首帧 / 尾帧静帧图（供视频-首尾帧工作流消费）**：本工作流不直接出视频，它的产物是「视频-首尾帧工作流」的**输入图**。管线顺序——先跑本工作流产出首 / 尾帧静帧图 → 图全部出完后，再跑视频-首尾帧工作流把这些图变成运镜视频。仅当某镜头首帧需含人物且人物数 ≤ 2（典型 1 背景 + 2 人物，最多 3 张输入图）时使用；首帧无人物、或人物数 > 2 时本工作流无法使用，该镜头改走视频-多参考（不单独出首帧图）。 |
| 视频-首尾帧工作流 | MiniMax H3 FL2VA | 首帧图 + 尾帧图 + 提示词 → 锁定起止画面的运镜视频 | **主渲染（运镜视频）**：需运镜 / 动作且能锁起止画面时使用。硬约束：① 首帧必须含人物（最好人物正面，否则人物不像）；② 该镜头人物数 ≤ 2；③ 镜头中途不转向其他人物。 |
| 视频-多参考工作流 | MiniMax H3 Ref2VA | 多张参考图（图 + 视频 + 音频）→ 绑定多参考的运镜视频 | **主渲染（运镜视频）兜底**：当 FL2VA 不适用时优先用——人物 > 2 / 无首帧人物 / 需中途转其他人物 / 需绑视频 + 音频参考。比 FL2VA **速度慢**；且必须按专有提示词规则指定传入图片的顺序与角色绑定（见 `分镜转视频.md`），不能乱序。 |

> 中文名为本技能自有命名；括号内为底层模型名（客观标识符，保持原样以便与 ComfyUI 工作流对应）。
> **主渲染 vs 资产预备**：每段分镜的「主渲染工作流」只从两个视频工作流（视频-首尾帧 / 视频-多参考）二选一；「文生图」与「图片工作流」是**资产预备**——文生图只出背景 / 概念图，图片工作流产出首帧 / 尾帧静帧图，二者按需喂给视频工作流，不与主渲染混选。
> 对应文件：`纯文生图_Z-Image.json`（文生图）／ `qwen2511 单图编辑版本`、`qwen2511 双图编辑版本`（图片）／ `（批量首尾帧）海螺生视频.json`（首尾帧）／ `H3-全能参考生视频（图9视频3音频3）优化版.json`（多参考）。完整清单见「四、当前拥有工作流与脚本」。

### R1 路由（主渲染工作流怎么选：出镜人数 × 是否含人物首尾帧，双因素）

> **选「视频-首尾帧（FL2VA）」还是「视频-多参考（Ref2VA）」不是凭感觉二选一**——它由**两个硬维度**共同决定（沿用 v1 判定，严禁简化为单一「二选一」口号）。两个维度任一命中 Ref2VA，就走 Ref2VA。

| 维度 | 取值 | 推导向 |
|---|---|---|
| **① 出镜人数** | 本段同时出镜的人物数 **≤ 2** | → 候选 FL2VA（首尾帧能锁起止且快） |
|  | 人物数 **> 2** | → 直接走 Ref2VA（多参考才能同时锚定多人，不丢中间角色） |
| **② 是否含人物首尾帧** | 首帧**含人物** 且 镜头中途**不换人** | → FL2VA（可用图片工作流出首/尾帧喂入） |
|  | 首帧**无人物** / 中途**要切到其他人物** | → Ref2VA（不单独出首帧，靠多参考直接带人物出视频） |

**决策流程（先判 ① 再判 ②，任一命中 Ref2VA 即走 Ref2VA）：**
1. 数本段出镜人数：**> 2 → Ref2VA**；≤ 2 进入第 2 步。
2. 看首帧是否含人物、中途是否换人：**无首帧人物 / 中途换人 → Ref2VA**；首帧含人物且中途不换人 → FL2VA。
3. 额外兜底：需绑**参考视频 + 音频**（口型 / 动作参考）→ 即便人数 ≤ 2 也走 Ref2VA。

- 判定结论必须写进每段 `生成视频的工作流` 字段，并在 `是否生成首帧图片` 同步写明「是 / 否 + 原因」（硬规则 5/6）。
- FL2VA 段的「是否生成首帧图片 = 是」联动 `生成图片的工作流 = 图片工作流`（Qwen 出首/尾帧）；Ref2VA 段该字段留空（不出首/尾帧）。

## 工作流程（功能 4：剧本 → 分镜，五步）

> 本流程把功能 3 的导演剧本（含世界书）变成 `提示词生成.md`。每段分镜最终要落盘成「背景是什么 + 用哪个图片工作流出首帧 + 用哪个视频工作流出视频 + 各自的提示词 + 时间」。上方「硬规则（红线）」全程适用。

### 第一步 · 拿到剧本，切成小于 14 秒的视频情节

- **输入**：功能 3 产出的导演剧本（含世界书）。
- **切镜（cut on change）**：按「地点 / 时间 / 视点主体 / 核心动作」任一变化切镜，每段是一个 **≤ 14 秒** 的独立镜头块（硬规则 1）。
- **一个镜头守一个主要动作**：别一句一镜（过度碎切），也别一个镜塞不住（过度合并）；无戏剧价值的切镜合并掉。
- **时长按节拍定，不按字数**：主动作给足（5–10s），过渡给短（2–4s），单段 ≤ 14s；超过就再拆段。
- **输出**：N 个分镜情节草稿，每段先用「段号 + 原剧情摘要」占位，待后面几步填齐。

### 第二步 · 背景认定（每个分镜情节绑定一个背景）

- 对每一段分镜，确定它用哪个**背景**：
  - **优先复用现有资产**：查 `工作配置.yaml` 指向的 `角色背景一览表.md` 的「背景清单」，若已有匹配的背景图文件名，直接引用该文件名（如 `木叶村口大道_背景.png`）。
  - **无现有资产**：从剧本 / 世界书里明确的**背景提示词**拿到（文字描述的场景 / 时间 / 画风），记为「场景背景描述」；后续由文生图（Z-Image）出图（必须无阴影无暗影，见「工作流提示词写法 › 4 背景提示词铁律」）。
- **同一场景的多段共用一个背景**：例如分镜 1、分镜 2 是同一场景（场景ID 相同），则两段背景描述**逐字一致、背景图同一文件**（硬规则 7，背景锁定）；只有场景ID 真正变化（故事环境变了）才允许不同背景。
- 每段记录：`场景ID` + **背景二选一**（填 `场景背景图` 已有文件名 **或** 填 `场景背景描述` 背景提示词，二者只填其一）；若选描述，则把 `是否生成背景图片` 置「是」并填 `背景图片存放位置`（Ref2VA 段最终必须以 `场景背景图` 为准，故选描述时生成后回填文件名）。

### 第三步 · 人物在背景中的固定占位（连续性锚点）

- 对每段出现的每个角色，在背景里给定**固定占位**，保证多个分镜之间人物位置不要大幅跳变：
  - **左右占位 + 上下占位**：多个人物要清晰描述，例如「人物 A 在画面左侧前景、人物 B 在画面右侧后景」。
  - **重点标识面向（朝向）**：每个角色必须写明面向（面向镜头 / 背对 / 侧脸 / 看向画面左 / 看向画面右 / 互看）；对话段双方面向对方，禁止留空让模型默认都看镜头（硬规则 8）。
- 把这些占位写进每段的「连续性锚点 › 人物位置」，作为跨镜保一致的交接点：固定地标 + 人物位置（逐角色朝向）+ 退场状态（= 下镜起始）。
- 同一场景的相邻段，人物左右 / 上下占位尽量一致，只在转场动机处才允许变化。

### 第四步 · 图片工作流（生成首帧 / 尾帧静帧图）

- **判定条件**：逐段检查「首帧是否有人物、镜头中间会不会切换人物」：
  - **人物数 ≤ 2 且中途不切换人物**（镜头始终同一批人、不转向其他人物）→ 确认用 **图片工作流（Qwen 图像编辑）** 生成首帧（FL2VA 段还需尾帧）。
  - **人物数 > 2 或中途要切换人物** → 本段不走图片工作流单独出首帧，改走视频-多参考（Ref2VA）直接带参考出视频（见第五步）。
  - **首帧无人物** → 不走图片工作流（无需人物首帧）。
- **生成提示词的标准（Qwen 首帧 / 尾帧）**，传入的资源与要素：
  - 人物 1 资源（参考图） + 人物 2 资源（参考图，若有）；
  - 背景图片（已有则传文件名）**或** 背景提示词（无图则文生图出）；
  - 人物方位（左 / 右 / 前 / 后）+ 面向（互看 / 看镜头 / 侧脸 / 低头 / 转头）；
  - 动作 / 表情 / 姿态 + 构图（中景，人物占下半部、背景占上半部）。
  - 提示词骨架与铁律见「工作流提示词写法 › 1 · Qwen 首帧 / 尾帧提示词」：每个角色单独声明「图片N的角色」、背景用「图片3的场景」，**绝不写人名**；禁批量泛称、禁外貌 / 服装 / 背景环境描写（这些由参考图负责，多写一个词都算过量）。
- 记录：本段 `是否生成首帧图片: 是` + `生成图片的工作流: "图片工作流"` + `生成图片提示词首帧 / 尾帧` + 出图后回填首 / 尾帧地址；若第四步判定不走图片工作流，则 `是否生成首帧图片: 否` 且 `生成图片的工作流` 留空。

### 第五步 · 视频工作流（确认主渲染 + 生成视频提示词与时间）

- **确认主渲染工作流二选一**（硬规则 5）：
  - **视频-首尾帧（FL2VA）**：当第四步判定人物 ≤ 2、首帧有人物、中途不换人时使用；消费图片工作流出好的首 / 尾帧图。
  - **视频-多参考（Ref2VA）**：当人物 > 2 / 无首帧人物 / 需中途转人物 / 需绑音视频时使用，比 FL2VA 速度慢，须按专有规则指定传入图片顺序与角色绑定。
- **执行顺序（不可逆）**：图片工作流出首 / 尾帧图、文生图出背景图，这些**资产预备全部出完**后，再跑视频工作流把图变成运镜视频。方向是「图 → 视频」，绝不能在图没出完时先跑视频。
- **生成视频工作流的资源**：把首 / 尾帧图（FL2VA）或多张参考图（Ref2VA：角色参考图 + 背景图末张）按对应工作流要求准备好。
- **生成视频工作流的提示词**：
  - FL2VA 段写**单行**提示词（`Picture 1 (start)` / `Picture 2 (end)` 锁起止），见「工作流提示词写法 › 2 · FL2VA 视频提示词」。
  - Ref2VA 段写**六段式**提示词（subject_definitions / summary / retention_analysis / detailed_description / overall_soundscape / non_diegetic_music），`<Subject N>` 一对一绑 `<Picture N>`，见「工作流提示词写法 › 3 · Ref2VA 六段式」。
- **时间**：本段 `视频时长`（≤ 14s，由节拍定）；对话写 `<d>[中文] 原文</d>`；无人说话段 `overall_soundscape` 写「无环境声」或仅关键动作声并标注「全程无人物发声」，禁人声类词（硬规则 9）。
- 记录：本段 `生成视频的工作流` + `生成视频的提示词` + `视频时长` + `Ref2VA资源分配`（Ref2VA 段）。

> 全部段落填完、过完下方「自检清单」后，写入 `工作配置.yaml` 指向的 `提示词生成.md`（即本技能主要工作文件），该文件即功能 5 / 6 / 7 的输入。

## 分镜 md 输出结构（schema）

> `提示词生成.md` 由「**顶部全局字段**」+「顶部事件链」+「N 个 `## 段<N>` 块」组成。
>
> **顶部全局字段（写在 `## 段<N>` 之前，全篇一份）：**
>
> | 字段 | 含义 | 填法 |
> |---|---|---|
> | `视频抽卡种子` | **本技能唯一的种子字段**（单一概念，见 `调用规范.md` 种子铁律）：最近一次 **0.1 / 0.2 MP** 抽卡所用的随机 `--seed`；**>= 0.3 MP 复用此值**（见 `分镜转视频.md §五`）。底层 FL2VA/Ref2VA 把值写到【顶部全局】，执行器（生成视频.py）跑完每段立刻把该值固化到【段内副本】，保证多段批量时每段保留自己的抽卡种子、成品档精准复用、不串段 | 顶部全局值由底层 py 回写（幂等覆盖）；段内副本由 执行器 固化；>=0.3 MP 段读取段内副本、绝不重新随机 |
>
> 每个段块字段如下（字段名与 提示词生成.md 段块字段对齐）：
>
> | 字段 | 含义 | 填法 |
> |---|---|---|
> | `## 段<N> — <标题>` | 段头：标题含人数 / 工作流简称 / 时长 / 切镜动机 | 如 `段1 — 穿越现身（2人，FL2VA，6s；动机：空间建立）` |
> | `生成图片的工作流` | **资产工作流**（出图用）：`图片工作流`（Qwen）/ `文生图`（Z-Image）；FL2VA 段用图片工作流出首 / 尾帧，Ref2VA 段本字段留空（不出首 / 尾帧） | 对应底层 JSON：`qwen2511 双图编辑版本` / `纯文生图_Z-Image.json` |

## 工作流提示词写法（要点）

### 1 · Qwen 首帧 / 尾帧提示词（资产预备，图片工作流）

> 仅 FL2VA 段需要首 / 尾帧图。Qwen 没有 `<Subject N>` 占位符，只能用**文字**锚定——**只用「图片N的角色 / 图片N的场景」指代，绝不写人名**；人物真实长相由 `--imageN` 传入的参考图锚定，背景由背景图锚定。

骨架：
```
图片1的角色在〔左/右/前景〕，图片2的角色在〔右/左/后景〕，以图片3的场景为背景。
〔若参考图含 2 人，给其中每个人分别朝向〕
〔动作/表情/姿态〕：…
〔构图〕：中景，人物占下半部，图片3的场景占上半部。
```
铁律：
- **每个角色单独声明**「图片N的角色」，禁止「两名青年 / 两人」等批量泛称（否则多人趋于同脸）；**不写人名**，人物由 image1 / image2 参考图负责。
- **空间位置必写**（左 / 右 / 前 / 后），否则模型居中对称、漂移。
- **双人各自朝向必写**（看镜头 / 看向画面左 / 互看 / 侧脸 / 低头 / 转头 / 回眸），否则都正脸看镜头。
- **禁外貌 / 服装 / 背景环境描写**：这些由参考图负责，只写「图片N的角色 + 位置 + 朝向 + 动作」指针，多写一个服装 / 场景词都算过量。
- 无阴影由脚本 / 功能 5 的 py 自动追加，正文无需再写。

### 2 · FL2VA 视频提示词（视频-首尾帧，单行）

> 批量 FL2VA 每段提示词必须是**单行**——首 / 尾帧图已作为图片喂入，用 `Picture 1 (start)` / `Picture 2 (end)` 标清首尾对应关系即可，只锁起止、中间运镜由模型补。

```
Picture 1 (start)：<首帧构图 + 起始动作，如 两人并肩站街道中央、神情惊愕转头四望>；Picture 2 (end)：<尾帧构图 + 结束动作，如 两人面面相觑、交换困惑眼神（互看）>。<左侧人物>说：<d>[中文] 台词</d>；<右侧人物>说：<d>[中文] 台词</d>（生成中文字幕，有清晰中文台词配音）
```
- **对话必须嵌进本段 `生成视频的提示词` 单行，不能只放 `对话处理`**：在 start/end 动作描述之后，用「位置指代」标出说话人并直接写 `说：<d>[中文] 台词</d>`。视频模型只消费本行提示词，`对话处理` 仅作「角色名→音色文件」的配音 / 字幕溯源记录。不嵌进来 → 模型不知道谁在说、口型对不上。
- **FL2VA 禁用官方 `<Subject N>/<Picture N>` 标签**：首尾帧只喂入起止帧画面、无角色参考图，模型既认不了中文名、也认不了 `<Subject N>`，只能用画面位置判断。说话人一律用「左侧人物 / 右侧人物 / 上方人物 / 中部人物 / 中左人物」等**位置指代**，且须与 start/end 描述里的位置一致、并与本段 `使用角色` / `人物位置` 锚定（如 左=王哲、右=李宝明）。
- **朝向一律以「镜头方向」为基准（统一坐标系，根除方向矛盾）**：描述人物朝向只用镜头相对表述——`镜头左 / 镜头右 / 镜头上 / 背对镜头 / 面向镜头`，禁用「背向彼此 / 面向远方 / 朝外」等无基准词。多人同望一个远处目标时，统一写「背对镜头、面朝远处岩壁」之类——两人方向自然一致，绝不会出现「一个朝左一个朝右」的分裂（这正是旧版 `背向彼此` 出错的根因）。**例外：当场景语义本就要求互相面对**（如 上课师生对视、对话双方、交锋对峙），用「互相面对 / 面向彼此 / 互看」显式写出即可，不强求镜头基准。
- 无对白段：本行末尾写「全程无人物发声」；`对话处理` 标「无对白纯动作」。
- 多人段在首 / 尾帧提示词里也要写明朝向：优先镜头相对基准（如 `背对镜头`）；互看场景写「互看 / 面向彼此」，避免都看镜头。

### 3 · Ref2VA 六段式（视频-多参考，必按格式）

> 9 图 3 视频工作流提示词严格按六段式，顺序不可乱；H3 只认 `<Subject N>` 占位符（绑定到 `<Picture N>`），**不认中文名**。

```
subject_definitions:
<Subject 1> 来自 <Picture 1>（角色A）；<Subject 2> 来自 <Picture 2>（角色B）；<Subject 场景> 来自 <Picture K>（场景背景图）
summary:
[reference generation] 目标视频展示…
retention_analysis:
<Subject 1>：fully_preserved - 外貌与服装来自该图；<Subject 场景>：fully_preserved - 背景保留自该图
detailed_description:
[Shot 1] <Subject 1> 站在画面左侧、面向 <Subject 2>（两人面对面）；<Subject 2> 站在画面右侧、面向 <Subject 1> 说：<d>[中文] …</d>。背景固定为 <Subject 场景>，全程保持一致、不更换背景。
overall_soundscape:
<无环境声（必要时仅关键动作声）；无人说话段末尾写「全程无人物发声」；禁人声类词>
non_diegetic_music:
N/A
```
铁律：
- **一个 `<Subject N>` 只绑一张 `<Picture N>`**，禁止把多张图压进一个 subject（否则中间位角色系统性被丢、串脸）。
- **`<Picture N>` 编号 = `--images` 传入顺序（从 1 数），无空槽**：环境 / 场景图放角色之后最后一张（Picture K+1），**绝不把环境塞进 Picture1 把角色推到 Picture2+**（否则 `<Subject 1> in <Picture 2>` 绑到环境图 → 串脸）。
- `detailed_description` 正文一律用 `<Subject N>` 引用，**绝不写中文角色名**；每个 `<Subject N>` 必须写站位 + 朝向（朝向优先镜头相对基准：`镜头左 / 镜头右 / 背对镜头`，如 学生上课写「背对镜头、面向镜头前方黑板」；**互看场景用「面向彼此 / 互看」**，如 对话双方、师生对视）。
- **对话用 `<Subject N> 说：<d>[中文] 台词</d>`（说话人锁定到参考图）**：有对白时，在 `detailed_description` 里用 `<Subject N> 说：<d>[中文] 原文</d>` 标出说话人（`<Subject N>` 绑定 `<Picture N>`，模型据此知道「哪张参考图的人在说话」并做口型对齐）；**绝写「李宝明说：」之类中文名**（模型不认中文名，会把名字当身份漂移）。无对白段在 `overall_soundscape` 末写「全程无人物发声」，`对话处理` 标「无对白纯动作」。
- 背景必须钉死：`背景固定为 <Subject 场景>，全程保持一致、不更换背景`。
- 服装 / 场景描写不能过多：有参考图时正文只做绑定，不重复描写。
- **每张参考图必须按序号「指派任务」（MiniMax 官方 reference-to-video 最高杠杆规则，必写）**：在 `subject_definitions` / `summary` 开头用一句把每张 `<Picture N>` 的角色钉死，例如「图片1（Picture 1）是主角A 的形象参考、图片2（Picture 2）是主角B 的形象参考、图片3（Picture 3）是场景背景」。不写这句，模型只能猜哪张是谁，极易串脸 / 丢中间角色。
  - **图片N 位置指定模板（写到 `detailed_description` 每句开头）**：`<Subject 1> 站在画面左侧、面向 <Subject 2>`；`<Subject 2> 站在画面右侧、面向 <Subject 1>`；`<Subject 场景> 为背景`。即「图片1 的角色在左、图片2 的角色在右、背景在最后」——位置必须和 `--images` 传入顺序一致。
  - **输出人物位置指定（每个 `<Subject N>` 必写）**：左 / 右 / 前 / 后 / 上 / 下 六选一固定站位 + 朝向（面向镜头 / 互看 / 侧脸）。不写位置模型会居中对称、漂移；多人必须各自不同站位。
- **输出人物的位置按 `<Subject N>` 指定**：每个 subject 必须写明它在画面中的位置（左 / 右 / 前 / 后 / 上 / 下），如「<Subject 1> 站在画面左侧、面向 <Subject 2>」；不写位置模型会居中对称、漂移。
- **参考图数量上限（MiniMax 官方）**：单次最多 9 张参考图 + 3 个参考视频 + 3 个参考音频（≤ 12 文件），参考视频 / 音频各 2–15 秒；本技能一个段通常只用「角色参考图若干 + 背景末张」，远未触顶，但不要把无关图塞进 `--images`。

### 4 · 背景提示词铁律（场景背景描述）

- **无阴影 / 无暗影**：脚本自动在提示词末尾追加「无阴影、无暗影」条款（见首尾帧生成规则.md）；绝不用负向「禁止阴影」兜底（实测会过曝）。
- **背景图空旷无人**：静态场景图一律「空旷无人」，路人 / 角色由 Qwen 合成阶段添加，不在背景图里出现人物。
- **禁止描写人物外貌与背景**（当已提供角色参考图与背景参考图时）：文字只写动作、表情、姿态、构图、人数、特殊效果；长相 / 发型 / 服装 / 建筑 / 颜色 / 天气由参考图提供。
