# 需求转情节（参考文档）

## 何时读 / 读它干什么 / 不读会漏什么

- **何时读**：功能 3 调用时——用户给了「情节需求」（小说大纲 / 小说正文 / 一段想法，三者之一），要转成可拍的剧本。
- **读它干什么**：按本规范把需求写成「导演的剧本」式情节，作为后续分镜与提示词的总依据。
- **不读会漏什么**：容易写成文学描写（比喻、心理、外貌、服装），导致后续出图 / 出视频时画面指令模糊、AI 自由发挥、人物与场景不一致；或剧本臆造嘈杂人声，污染视频音轨。

---

## 一、功能定位（输入 → 输出）

- **输入**：用户发来的「小说大纲 / 小说正文 / 零散想法」三者之一。
- **处理**：把需求转写成「导演剧本」式情节。**角色长相、服装、背景一律不在此处描写**——这些由 `角色背景一览表.md` 的参考图锚定，剧本只写可拍的戏。
- **输出**：剧本文本 → 建议写入 `剧情生成.md`（即 `工作配置.yaml` 中「剧情生成文件」指向的完整剧情）；**同时产出 `世界书.md`（世界观锚点，详见第九节）**，由 `工作配置.yaml` 中「世界书」字段指向。
- **关联**：剧本产出后调用 `生成剧情角色表.py` 枚举角色并写入 `角色背景一览表.md` 的「剧情角色清单」（详见第八节）；后续功能 4（剧本 → 分镜）读取本剧本继续拆镜，其背景基调统一取自本步骤产出的 `世界书.md`。

## 二、剧本红线（硬规则，必须遵守）

1. **禁止比喻**：不写「像…一样」「仿佛…」「如…般」等修辞。只写能看见、能听见的具体事物。
2. **禁止心理活动 / 心态描写（含旁白式心态总结）**：不写「他心里…」「她感到…」「内心…」「似乎在想…」等内在情绪，也**禁止用叙述者口吻替角色下"他明白了 / 她信了 / 彼此了然"的结论**（如「不必多说，两人都明白了」「心照不宣」「瞬间懂了」这类旁白式心态总结一律禁）。**认知与情绪必须靠可见镜头外化**——用动作 / 台词 / 表情 / 目光接触 / 肢体反应等具体可见行为展现，不得用旁白代角色下判断。例：❌「不必多说，两人都明白了：他们真的穿越了」→ ✅「二人对视一眼，李宝明抬手指向远处山壁上的四张巨脸，王哲跟着望去、点头」。
3. **禁止写角色样貌**：不描写长相、发型、五官、身材、年龄、肤色、配饰等。角色特征由参考图提供，文字只写「保持图中人物特征」。
4. **禁止指定服装**：不写穿什么衣服、什么颜色、什么款式。服装同样由参考图锚定，剧本不指定。
5. **可以指定动作**（含表情 / 姿态 / 构图 / 镜头运动 / 互动关系 / 特殊效果）：这些是参考图无法表达的信息，**明确允许**写。动作是剧本核心。
6. **音效栏默认只需人物说话声，其他声音除非必要；禁止 BGM、禁止一切环境声**：人物说话声由「对话」栏台词经音频配置阶段按「角色名 → 音色文件」合成，**音效栏默认不写**即可带说话声。仅在确有必要时，才在音效栏写与可见动作直接对应的**关键动作声**（如武器挥击 / 拳脚击打 / 摔落）。**禁止**写任何 BGM（背景音乐）与任何环境声——含自然环境声（风声 / 雨声 / 海浪 / 虫鸣）与环境人声底噪（嘈杂 / 低语 / 喊声 / 教室杂音）。不靠 BGM、不靠环境声补音量。
> **注意**：本禁令锁「音效栏」的 BGM 与环境声；角色自身的台词声音来自「对话」栏、由音频配置合成，**不受此限**——有对话的场自然有说话声，音效栏不必为此重复写。
7. **背景优先复用现有素材，素材没有的要单独生成提示词版本背景**：剧本涉及背景时，优先引用 `角色背景一览表.md`（由 `工作配置.yaml` 的「角色背景一览表」指向）中**已登记且有对应资产图**的背景，直接复用其文件名，不凭空新造背景描述。
- **素材（背景资产图）已存在** → 直接引用背景图文件名。
- **素材（背景资产图）没有** → 单独生成「提示词版本背景」：一段可直接喂给图片工作流生成该背景图的背景提示词（必须无阴影、无阴暗），并把「背景名 + 该提示词」补登记到一览表，供功能 4 分镜阶段据此出图。
- 确有全新场景、一览表里完全没有的 → 先补充登记到一览表，再按上述「有图用图、无图出提示词」处理。
8. **只写导演的剧本**：以「画面 + 声音」为单位，写清「谁、在什么背景、做什么动作、说什么、镜头怎么拍、什么声音」。背景只引用 `角色背景一览表.md` 中已登记背景名，不再另写环境描写——环境已由背景锁定，重述即冲突。
9. **每个情节单元（场）独立成块**，块内至少含：场号、背景（即原「场景」，引用 `角色背景一览表.md` 中已登记背景名）、人物占位、表情、动作、对话、镜头、面朝方向、音效。

> **规则说明**：以上红线为本技能自定规则，规则正文即权威依据，无外部依赖。

## 三、情节因果层（戏剧驱动 · 摘自 short-drama-develop）

> 本节把"需求转成情节"从"格式正确"再往前推一步：确保每段情节在**戏剧因果**上站得住，而不是漂亮空镜堆砌。下游分镜（功能 4 的 `分镜规则.md`）只管 shot 级连续性，因果是否成立由本节把关。

### 3.1 故事引擎（驱动多元 · 爽文向）

每段情节必须有清晰的**驱动源**与**爽点**，禁止温吞无起伏：

- **驱动源不止一种**：可以是**主角的欲望**（想变强 /爱美女所以各种手段，比如催眠，改写认知，阴谋诡计 / 想打脸 / 想守护）、**系统的强迫**（任务 / 规则 / 异能绑定推着走）、或**外部事件**把人卷进来——不靠"制造压力"硬憋冲突。
- **每段都要给一个爽点**：碾压 / 反杀 / 美女展示 / 打脸 / 获得 / 揭晓，满足感来自"预期被超额兑现"，而不是靠焦虑拉扯。
- **状态仍要变，但方向朝上**：实力 / 收获美女 / 地位 / 资源 / 声望 / 系统赠与 /信息——主角这头持续往上走，不靠"付出代价"推进。

### 3.2 欲望 · 行动 · 状态跃升

爽文的本质是主角**想要什么就去拿**，并拿得漂亮。

- 每段结尾问一句："这场之后，主角得到了什么 / 站到了哪"（实力涨了 /得到美女 / 脸打了 / 资源到手 / 秘密揭开）。
- 没有正向变化的段，要么删，要么补一个"爽点兑现"。

### 3.3 铺垫 → 兑现（伏笔回收）

- 前面埋的钩子 / 伏笔，后面必须回收；**禁止悬空**。
- 暂不能回收的，在段末显式标 `待回收：<内容>`，不假装忘了。
- 不要新造一个钩子却永不兑现。

### 3.4 场间交接（为什么接上一段）

每段写清因果接头，接不住不进下一段：

- **进入状态**：本段开始时角色 / 局势处在什么状态。
- **当段追求**：这段角色想拿到什么。
- **阻力**：挡着他的什么。
- **因果升级**：这段相对上一段，冲突推进了什么。
- **出去的钩子**：段末留一个未解（下一个被打脸的对象 / 新出现的机缘），逼出下一段。

> 场景 ID 变化的硬切动机已在功能 4 的 `分镜规则.md` 约束；本节只管"事件为何接连发生"。

### 3.5 拒绝配方（工艺默认）

- **不要用固定情节点 / 转折时刻 / 篇幅比例替代因果判断**（如"每 3 段必反转"是错的）。
- 张力靠因果自然起伏，不靠刻度尺。

### 3.6 契约边界（轻量）

- 区分用户给定的**不可改事实**（题材 / 结局承诺 / 已定角色）与**可探索空白**；不改既定事实，空白里才发挥。

### 3.7 女性角色情节编排（吸引力向）

面向短视频（抖音 / 视频号 / B站）的爽文变现，女性角色是提升完播与互动的重要钩子。**但必须挂在因果链上**，不能塞无戏剧功能的纯展示镜头（否则被 3.5 拒绝配方拦下）。

- **形象锚定靠参考图，不靠描写**：女性角色的高颜值 / 造型由参考图锚定（功能 4 资产表），情节层只点名 + 给戏剧功能，不写样貌长相（呼应第五节无样貌红线）。
- **关系即看点**：女性角色与主角的关系推进（欣赏 / 依赖 / 对立 / 羁绊）本身制造张力——她站主角这边、被主角实力折服、还是被反杀打脸，都是爽点放大器。
- **驱动源可用"守护"**：想守护某个女性角色（家人 / 同伴 / 羁绊对象）可直接作为 3.1 的主角欲望驱动，天然带情绪钩子。
- **女性反派 / 轻视者 = 打脸倍增器**：让看不起主角的女性角色被实力反杀、当场改观，比打脸男配更抓眼。
- **反差爽点**：高冷 / 强势女性角色被主角实力或格局折服的反差，是稳定的吸睛段落。
- **禁忌**：不为流量牺牲因果（硬塞无功能镜头记作不通过）；不靠低俗 / 擦边，靠形象塑造 + 戏剧张力拿流量。

### 3.8 情节自检（戏剧维度，补充文末自检清单）

- [ ] 每段都在推进因果链，无纯展示空镜段？
- [ ] 每段结尾有明确的正向状态变化（得到了什么 / 站到了哪）？
- [ ] 所有伏笔都已回收或标 `待回收`？
- [ ] 每段都能回答"为什么接上一段"？
- [ ] 没有用固定配方（必反转 / 必高潮）替代因果？
- [ ] 女性角色相关情节是否挂在因果上、确有戏剧功能（非硬塞展示）？

## 四、生成流程：先扩写剧本，再切分镜头（func3 剧情生成铁序）

> 🔴 **强制铁律（最高优先级 · 必须严格照此执行，不得有任何简化 / 跳步 / 偏离）**：func3 剧情生成**必须严格按照「① 先扩写剧本 → ② 再切分镜头」两阶段顺序执行**。**禁止**以下任一行为：跳过扩写剧本直接填镜头模板、颠倒两阶段顺序、凭模板照葫芦画瓢忽略剧情、对下方「扩写剧本规则 / 切分镜头规则 / 结构铁律 / 诉求—回应铁律 / 镜头切换链」任一条打折扣。**任何偏离都一律判为生成失败、必须重做**——这不是建议，是硬约束。生成前先把整节读完、逐条对上，再动手。

> ⚠️ **func3 剧情生成的唯一正确顺序**：拿到用户需求后，**第一步必须先扩写剧本（像专业编剧一样写通顺的散文剧本），第二步才把剧本切分成镜头**。**禁止一上来就填镜头模板字段**——那会直接掉进「只顾填空、忽略剧情连贯」的坑（本技能反复踩过的雷）。扩写剧本是连贯性与因果性的唯一来源；切分镜头只是把已通顺的剧本机械拆成可拍的镜头，不得另起炉灶。

### 前置硬规则：剧情生成.md 的三段强制结构

`剧情生成.md` 的**强制结构**为三段，顺序不可颠倒：
- **顶部 `## 用户的剧情需求`**：忠实保存用户提供的原始需求（小说大纲 / 正文 / 想法原文）。不改写、不精简、不自行发挥；是下方一切的唯一依据。
- **其下 `## 一、扩写剧本`**：专业编剧风格的**连贯散文剧本**（见下方「扩写剧本规则」）。剧情 / 对话 / 表情动作 / 因果全部在这里写顺、写合理。这是 func3 的主交付物之一，**必须落盘**。
- **其下 `## 二、切分镜头`**：**严格从上方「扩写剧本」逐句切出**，不得新增剧本里没有的情节。镜头结构与规则见下方「切分镜头规则」。

> 若用户尚未给需求：顶部段标注「待用户提供」，但**不得**跳过直接写；用户提供后填原文，先重写「扩写剧本」、再据其重切「切分镜头」。

### 扩写剧本规则（第一阶段 · 先写顺）

扩写剧本是 **prose，不是模板字段**，且**必须严格按下面 1–5 条逐条落实、不得打折扣**。写的时候必须满足：
1. **用户需求驱动**：每一处情节都服务于顶部「用户的剧情需求」，不偏离、不自行加戏。
2. **§二 剧本红线**：无比喻 / 无心态词 / 无样貌 / 无服装 / 无 BGM / 无环境声；背景复用已登记。
3. **§三 情节因果层**：驱动源 + 爽点 + 状态跃升 + 铺垫→兑现 + 场间交接，剧情连贯不跳。
4. **像专业编剧**：对话自然、有信息量、符合人物性格；表情动作具体可见、服务因果；分场清晰（场 = 一个时空块）。
5. **⚠️ 「诉求—回应」交互铁律（关键，本技能曾因缺它翻车）**：当剧情中某个目标**需要他人授权 / 配合 / 安排**才能达成（如 求职 / 求任命 / 求授权 / 求带人），**必须在剧本里显式写出两段对话**：① 角色主动向对方提出诉求（如「我想进忍者学校任教」）；② 对方明确回应 / 安排（如「那班就交给你带」）。**禁止以「获信任后自动就任」「上位者主动赐予」等方式跳过这段交互**——「出任学校老师」曾被写成无铺垫、无对话，根因正是这条没写。
6. **⚠️ 同框角色须有互动（非自言自语）**：凡 ≥2 名角色同框的场 / 镜头（尤其抵达新环境、初见关键事物、日常相处），须有角色之间的对话或动作呼应（彼此说话、回应、视线 / 肢体互动），**禁止全员静默只做动作当道具**。单人镜头或刻意留白可无声。重点是「人在一起会交流」，不是逼每人自言自语。
7. **⚠️ 须有日常质感（穿插生活行为）**：除推进主线的情节外，须穿插角色**日常化行为 / 动作**（整理装备、环境互动、随手小事、生活细节、非任务向闲聊），使角色「在生活」而非「只走剧情」。日常镜头可无声，重在行为质感，不是逼说话。
8. **⚠️ 角色相遇须自然发生（禁止无故跳到会面）**：角色之间（尤其主角与目标人物）的相遇 / 会面，须有可见的过程桥接——**决策 → 移动 → 抵达 / 偶遇**，不得为推进剧情凭空硬切到会面现场。能在日常场景自然遇上（如大街上偶遇、村道擦肩、集市碰面）就优先用自然相遇，而非直接跳进办公室 / 密室等封闭会面点。场景 ID 变化必须交代「怎么从 A 到 B」。

### 切分镜头规则（第二阶段 · 再切镜）

切分镜头**必须严格从「扩写剧本」逐句切出**（不得新增剧本里没有的情节），每段对话 / 动作 / 景别变化对应一个镜头；下方「结构铁律」与四条约束**逐条强制执行，不得简化、不得合并镜头**。

> **结构铁律（镜头 ≠ 场，必读后再切）**：
> - 一个 **场（时空块）** 由 **1 个或多个 镜头（shot）** 顺序组成；**每个镜头是一个独立镜头，只承载一个空间主体 / 一个景别意图**。
> - **镜头切换链：镜头从 A 转向 B，B 必须是单独一个镜头；镜头从 B 转向其他（C / D …），其他也各自必须是单独一个镜头**。即——**任何镜头切换，目标镜头（无论第几个）都独立成镜，不存在「并进上一个镜头」「把两个主体塞进同一镜」**。转场在镜头之间用「切 / 叠 / 淡」标清动机（§六）。
> - **建立镜头（地标 / 环境确认）与人物对话镜头必须拆成不同镜头**，禁止合并。例：「火影岩」是确认身处木叶的建立镜头，单独成镜（拍地标 + 角色望向它的反应，可无对白）；两人对话是另一个镜头。不要把「看向火影岩」塞进对话镜头的同一行，也不要把地标 / 环境反应散到表情 / 动作 / 对话 / 面朝各栏去和对话混合。

```
# ⚠️ 切分镜头：每个镜头独立成镜；镜头切换链 A→B→C 中 B、C 各自独立；严格从「扩写剧本」切出，不新增情节
场 <编号>  <日/夜> <内/外>  <背景：引用 角色背景一览表 中已登记背景名>
（本场由「扩写剧本」第 X 场切出；场因果：{场间交接 + 爽点 + 状态跃升 + 铺垫→兑现，摘自扩写剧本}）

  镜头 <n>（<景别/运镜意图，如 火影岩全景建立>）
  遵守规则：{本镜头须满足的红线 / 因果 / 风格}
```

## 六、导演层注意事项（剧本阶段就要埋好意图）

以下细节在功能 4 分镜阶段展开，但剧本阶段先把意图标清，避免后续返工：

- **转场动机构**：场景 ID 变化时必须有连接镜 / 交代句 / 显式 HARD CUT 理由，禁止无交代硬切不同地点。**含角色会面**：不得省去「决策 → 移动 → 抵达 / 偶遇」过程，优先自然相遇（见扩写剧本规则 ⑧）；「两人突然出现在火影办公室」这类凭空跳到会面点属硬切，必须补桥接（怎么从 A 走到 B、或在哪偶遇）。
- **对话必要性**：两人及以上同框、且该场有信息 / 情绪 / 关系变化 → 必须写对白，或显式标注「无对白纯动作 / 刻意沉默」；静默须是刻意选择，不能漏写。
- **朝向 / 背景**：剧本里点明双人是否面对面、场景是否同一背景；具体朝向与背景图锁定在分镜阶段落定。

> 完整的事件链 / 节拍表模板与导演自检清单，见功能 4 的 `分镜规则.md`（分镜前必读）。

## 八、剧情角色枚举与匹配（生成 剧情角色清单）

`角色背景一览表.md` 是本技能**唯一的角色 / 背景资产登记处**，内含两大部分：
- **现有资源角色清单**：已入库的角色参考图（由功能 2 `重命名.py` 自动写入，每行 `- \`参考图文件名\` | 简述`）。
- **剧情角色清单**：本剧本出现的所有角色，及其匹配到的资源角色（参考图）、**角色定位简短描述**（性格 / 身份 / 在故事中的定位，如「冷傲天才」「怯懦书生」）。由本步骤生成 / 更新。

  > **角色定位描述是「用户可编程」字段**：脚本默认按剧本表现推断一个简短定位（性格 / 身份）；**用户可直接改成自己的设定**（例如把默认的「冷傲」改成「害羞」）。后续功能 3 生成剧本时**必须读取并采纳用户最终确认的性格定位**——用户改了性格，剧本里该角色的言行 / 互动基调须随之调整，不能无视。

**步骤（枚举 → 匹配 → 落盘）**：
1. 枚举剧本（`剧情生成.md`）中出现的**全部角色名**。
2. 逐个查 `角色背景一览表.md` 的「剧情角色清单」：
   - **已存在** → 不加，跳过。
   - **不存在** → 新增一行，并**默认从「现有资源角色清单」按性别匹配一个资源角色**（同性别取首个，确定性可复现；详见 `调用规范.md` §三「按性别匹配，替代随机」）作为默认匹配（参考图），写入「剧情角色清单」。
3. 若「现有资源角色清单」为空（尚无任何资源），新增的剧情角色标记「待补（无现有资源）」，待后续入库资源后手动改匹配。

**由脚本执行**：上述 1–3 由 `py脚本/生成剧情角色表.py` 自动完成——传入全部剧情角色清单（`--角色` 可重复 / `--文件`），脚本读 `角色背景一览表.md`、自动跳过已登记、为未登记角色默认随机匹配并写回。

> 注意：默认随机匹配只是「先用现有资源顶上、保证流程不卡」；最终每个剧情角色应替换为正确资源角色（手动改「剧情角色清单」对应行的「匹配资源角色」）。

### 8.1 剧情角色详情表（防后续剧情脱离关键要素）

功能 3 转情节时，**必须同时产出「剧情角色详情表」**，写入 `角色背景一览表.md`（置于「剧情角色清单」之后）。它是后续开发 / 续写剧情时的**状态锚点**——角色言行、关系、数值须与之一致，不能凭空漂移。

> 与「剧情角色清单」的区别：清单只做 名字↔参考图 匹配 + 一句定位（由 `生成剧情角色表.py` 自动枚举）；详情表是 **AI 按剧情内容推断的角色状态**（性格 / 精神状态 / 当前行动 / 关系数值 / 堕落值），py 不自动生成，由功能 3 的 AI 直接写入。

**表1 角色详情（角色维度，每人一行）**

| 剧情角色 | 性格 | 精神状态 | 当前正在做什么 | 堕落值 | 备注 |
| --- | --- | --- | --- | --- | --- |
| `<角色>` | `<稳定人格特质，如 冷傲/怯懦/阴狠>` | `<当前心理快照，如 亢奋/警惕/麻木/崩溃>` | `<剧情当前时点的具体行动>` | `<默认 0；仅发生强行身体关系时填>` |  |

- 性格：稳定人格特质。精神状态：当前心理快照（随剧情可更新）。当前正在做什么：当前时点行动。堕落值：默认 0，仅当该角色发生过「强行身体关系」时填写（联动表2）。

**表2 角色关系（关系维度，主体→对象 定向，每对关系一行）**

| 主体 | 对象 | 关系类型 | 数值(0–100) | 说明 |
| --- | --- | --- | --- | --- |
| `<角色A>` | `<角色B>` | `<亲密/仇恨/惧怕/控制>` | `<对应 亲密度/仇恨度/惧怕度/控制度，0–100>` |  |

- 关系类型：`亲密` / `仇恨` / `惧怕` / `控制` / `朋友`/ `肉体需求`；数值对应 `亲密度` / `仇恨度` / `惧怕度` / `控制度`/ `需求度`，0–100（0=无，100=极致）。
- 若关系类型=亲密 且发生了强行身体关系：说明列记 `强行次数=N`，并把堕落值按公式算入表1 该角色「堕落值」。
- 堕落值公式：`堕落值 = min(100, 强行次数 × 12 + 亲密度 × 0.3)`。

**维护规则（活文档）**：功能 3 首写时按需求推断填初值；后续功能 4 拆镜 / 续写剧情时**必须读取**本表，若剧情推进改变角色状态（亲密度升、仇恨加深、发生强行关系致堕落值涨），须**回写更新**本表，保持前后一致。

## 九、世界书生成（世界观锚点，①）

功能 3 不只是转剧本——**同时产出 `世界书.md`（世界观锚点）**，作为后续出图 / 出视频的统一背景基调来源。

**本步骤规则**：
- 读用户的需求 / 小说片段，生成 **时代 / 地理 / 势力 / 审美 / 材质**，统一后续出图 / 出视频的背景。
- 角色出图、场景出图、视频都从世界书取基调，保证风格 / 时代一致。
- **输出位置**：写到工作目录 `世界书.md`（与 `剧情生成.md` 同目录，由 `工作配置.yaml` 的「世界书」字段指向）。
- **场景连续性地标**：每个跨多镜复用的场景，除基调外必须额外锁定 **连续性地标**（固定物体 + 屏幕位置）、情绪子空间、重要道具——保证跨镜场景不跳变（同一张桌子这镜在左、下镜到右）。
  - ⚠️ 场景卡**不含人物**（不出现脸 / 手 / 剪影），只记环境；人物一致性由 `角色背景一览表.md` 的角色卡负责。

> ⚠️ **格式与规则已互相关联**：下方模板**每个字段都内嵌了「必须遵守的规则 + 需求来源」**，规则不再在格式外、而在格式内。生成时**逐字段填**——先写「遵守规则」「需求来源」再写「内容」；漏任一项 = 无效、须重做。
