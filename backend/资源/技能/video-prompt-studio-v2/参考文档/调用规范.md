# 调用规范（py 调用契约 · 单一可信源）

> **何时读**：调用任何一个 `py脚本/*.py` 之前 / 排查「调用出错」「回写没生效」「参数传错」时读。
> **读它干什么**：每个 py 的命令行参数（必填/可选/默认）、它强制执行的规则、它把结果**回写到哪个文件的哪个字段**，全部列清——照此传参就不会调错。
> **不读会漏什么**：传错 `--output-dir` 导致图落在 ComfyUI 盘找不到、漏传 `--comfy-output` 无法自动拷贝、seed/mp 铁律违反导致成品档内容不一致、回写字段名写错导致下游读不到。
>
> 本文件是「调用契约」总表；各功能的**业务规则**（提示词写法、路由逻辑、人物一致性）在对应 `分镜规则.md` / `分镜转视频.md` / `首尾帧生成规则.md` / `图片重命名规范.md` 里，本文件只管「怎么正确调用 py」。

## 二、功能 2：重命名.py

| 项 | 内容 |
|---|---|
| 必填（二选一） | `--config <工作配置.yaml>`　或　`--dir <路径>`（可重复；`角色:<路径>`/`背景:<路径>` 指定类型） |
| 可选参数 | `--project-dir`、`--comfy-url`(默认 `http://127.0.0.1:8188`)、`--backend`(默认 `http://192.168.31.131:8488`)、`--backend-model`、`--busy-threshold`、`--no-fallback`、`--consecutive`(默认 3)、`--timeout`(默认 120)、`--dry-run`、`--no-txt`、`--no-rename`(仅重建清单不改名) |
| 产出 | 原地重命名图片；`{原名}_反推.txt` 存档（默认写）；回写 `角色背景一览表.md` |
| **回写位置** | `角色背景一览表.md` → 「现有资源角色清单」（角色图）/「背景清单」（背景图），每行 `- \`文件名\` \| 简述` |
| 规则 | ①跳过判定：角色以 `单一视图_`/`多角度视图_` 开头、背景以 `_背景.png` 结尾 → 跳过（断点续跑）；②远程优先，连续失败 ≥ `--consecutive` 次转 ComfyUI 反推；③单实例锁防队列堆积；④重名追加 `_2/_3`；**⑤默认对齐（无需加参数）：扫描目录时，凡是已规范命名的图片，若一览表里没有，直接登记进「现有资源角色清单 / 背景清单」、不重新识别。即「配置改指真实目录后，把文件夹已有图片对齐进 md」是默认动作，不是可选功能** |

**默认对齐行为（重点）**：
- 跑 `重命名.py` 时，对**已规范命名**的图片（角色 `单一视图_`/`多角度视图_` 开头、背景 `_背景.png` 结尾），脚本不再识别、直接把文件名写进一览表对应清单；清单已有则跳过（幂等）。
- 效果：当 `工作配置.yaml` 的 `角色资源所在目录 / 背景资源所在目录` 改指真实目录（如 `火影\真人版加生提示词\角色`、`火影\真实场景`）后，重跑本脚本即可把真实目录里的图片对齐进一览表，**无需任何额外参数、无需重识别**。
- 仍会识别的，只有那些**未规范命名**的图片（如 `猿飞日斩_单一视图.png` 这种前缀写反的）——它们走正常识别改名流程。

调用示例：
```bash
python 重命名.py --config "D:/proj/工作配置.yaml" --dry-run        # 只预览
python 重命名.py --config "D:/proj/工作配置.yaml"                  # 实跑 + 回写一览表（含默认对齐）
```

> ⚠️ 已知 minor：dry-run 仍会先调远程识别（为预览目标名），遇到畸形文件名（mojibake）时 ComfyUI 回退会失败 → 被捕获为 `[warn] 识别失败，跳过`，不崩溃、不改名。

## 三、功能 3：生成剧情角色表.py

| 项 | 内容 |
|---|---|
| 必填（二选一） | `--角色 <名>`（可重复）　或　`--文件 <每行一个角色名>` |
| 可选参数 | `--config <工作配置.yaml>`、`--project-dir`、`--seed` |
| 产出 | 回写 `角色背景一览表.md` |
| **回写位置** | `角色背景一览表.md` → 「剧情角色清单」（**必须 5 列**：`剧情角色 \| 匹配资源角色（参考图） \| 角色定位简短描述 \| 匹配方式 \| 备注`） |
| 规则 | ①已登记角色自动跳过（幂等，可反复跑）；②**新角色按性别匹配参考图**（替代旧版随机）：脚本从「角色资源所在目录」走查 `父目录名(男/女)=性别`、`子目录名=角色名` 建立性别映射，再筛「现有资源角色清单」中**同性别**的参考图、确定性取首个；无性别信息时回落默认首图；无现有资源则标「待补（无现有资源）」；③章节按**标题行**定位（勿在正文内联「## 章节名」字样） |

**按性别匹配（重点，替代随机）**：
- 旧版 `random.choice` 全池随机会把男角配到女图（如 李宝明→女图），已废弃。
- 新逻辑：依据目录结构（如 `角色\男\李宝明` → 李宝明=男）得到角色性别，再在同性别参考图里确定性匹配，杜绝性别错配。
- 同性别内取首个是确定性的（按文件名排序），不再随机，可复现。
- `--seed` 保留兼容但已不影响结果（匹配为确定性）。

调用示例：
```bash
python 生成剧情角色表.py --config "D:/proj/工作配置.yaml" --角色 李宝明 --角色 王哲 --角色 猿飞日斩 --角色 雏田 --角色 天天 --角色 小樱
```

> ⚠️ **schema 硬约束**：「剧情角色清单」必须是 5 列表格。若只写 2 列（`剧情角色 \| 参考图`），`load_story_rows` 读不到已登记 → 功能 3 会误判「0 已登记」并**重新随机匹配覆盖**。脚本已做容错（兼容 2/3/4/5 列），但一览表请始终用 5 列规范。

### 5.1 子进程调用契约（已硬化，勿手改参数名）

**调 Z-Image文生图.py（出背景）：**
```
Z-Image文生图.py --prompt <场景背景描述> --copy-to <暂存目录> --comfy-url <url>

```
- 落点：`--copy-to` 暂存；功能 5 自己 `shutil.move` 到 `<图片输出目录>/<场景ID>_背景.png` 并回写。

**调 Qwen出图.py（出首/尾帧，general 三图）：**
```
Qwen出图.py --mode general --image1 <角色参考图1> --image2 <角色参考图2> --image3 <背景图>
            --prompt <首/尾帧提示词> --output-dir <图片输出目录> --frame-name <段N_首帧.png>
            --comfy-url <url> [--negative <负向>] [--comfy-output <根>]
```

- 落点：`--output-dir/--frame-name`（功能 5 用「图片输出目录 + 段N_首帧.png」）；功能 5 自己回写 `生成图片首帧地址/尾帧地址`。

## 七、功能 6 / 功能 7：FL2VA首尾帧视频.py / Ref2VA多参考视频.py

| 项 | 内容 |
|---|---|
| 必填 | `--config <工作配置.yaml>`（定位 `--storyboard`=提示词生成.md） |
| 可选 | `--megapixels`（mp，功能 7 透传用户值）、`--seed`、`--comfy-url`、`--comfy-output`、`--duration`（覆盖时长） |
| 读取字段（`提示词生成.md` 对应段） | `使用角色`→首尾帧图/参考图、`视频时长`、`生成视频的提示词`、`Ref2VA资源分配`(多图顺序) |
| 产出 | `<视频输出目录>/<段N>.mp4`（或工作流默认前缀） |
| **回写位置** | `提示词生成.md` 对应段：`生成视频地址`；`提示词生成.md` **顶部全局字段**：`视频抽卡种子`（仅 `--seed` 不传=随机抽卡时回写，供 >0.2 MP 复用） |
| 规则 | ①mp 铁律：0.1/0.2 抽卡（不传 --seed 随机），>0.2 必须读顶部 `视频抽卡种子` 复用、**绝不重新随机**；②seed 铁律：随机种子回写顶部，下次 0.3+ 才能用上；③Ref2VA 多图 `--images` 顺序：图片1 在左 / 图片2 在右 / 背景末张；④提示词一律中文 |

调用示例：
```bash
# 逐段：由执行器把该段首/尾帧目录传给 FL2VA（底层无 --seg，段号由执行器控制）
python FL2VA首尾帧视频.py --config "D:/proj/工作配置.yaml" \
  --first-dir "D:/proj/视频/_fl2va_段2_first" --last-dir "D:/proj/视频/_fl2va_段2_last" \
  --prompts-file "D:/proj/视频/_fl2va_段2_prompt.txt" --megapixels 0.1
python Ref2VA多参考视频.py --config "D:/proj/工作配置.yaml" \
  --images char1.png char2.png bg.png --prompt "$(cat D:/proj/段1_多参考提示词.txt)" \
  --megapixels 0.3   # 0.3 必须复用顶部视频抽卡种子
```

> ⚠️ FL2VA / Ref2VA **自身没有** `--seg` / `--only` 参数（实测 argparse 无此两项）。「指定段 / 逐段」由**执行器（驱动 / 编排脚本，见 §7.1）**通过传不同的 `--first-dir`+`--last-dir`（FL2VA）或 `--images`（Ref2VA）实现，而非给底层脚本传段号。

> 功能 6/7 的**官方执行器是 `生成视频.py`**（随技能分发，见 §7.1），它按 `分镜转视频.md` 路由**逐段**调 FL2VA / Ref2VA，并内置 seed 铁律与按段固化。功能 7 = 功能 6 仅处理指定段（`--only`）+ 按用户 mp 透传 `--megapixels`。

### 7.1 官方执行器 `生成视频.py`（功能 6/7 唯一推荐入口）

`py脚本/生成视频.py` 是功能 6/7 的**官方编排器**，严格按上面契约逐段路由调 FL2VA / Ref2VA，并硬化三件事（防调用出错）：
- **按段固化 seed**：底层脚本把 `视频抽卡种子` 写到【顶部全局】字段，批量多段会互相覆盖 → 执行器在每段跑完后立刻把该值 `write_back_field` 到【段内】`视频抽卡种子`，保证每段保留自己的抽卡种子，供 >=0.3 复用精准命中本段。
- **mp 铁律分支**：`--mp <= 0.2` 不传 `--seed`（底层随机并回写顶部）；`--mp >= 0.3` 读该段【段内】`视频抽卡种子` 传 `--seed` 复用，缺失则告警退化（绝不静默重新随机）。
- **失败直接跳下一段**：单段底层脚本失败 → **不**取消 ComfyUI 任务、不清理队列，直接 `continue` 后续段（每段独立视频，互不影响）；等待时间无限。
- **显存管理（实测）**：ComfyUI 不会自动回收「中断 / 失败任务」占用的显存，调试期反复失败会累积孤儿显存，跑到后段显存占满 → 权重落 CPU → 报 `Input type (torch.cuda.FloatTensor) and weight type (torch.FloatTensor) should be the same`。**真因是失败 / 中断任务污染、非「段间没清显存」**，只能靠**重启 ComfyUI** 清除；`free_vram()` 仅 best-effort 段间卸载、无法回收孤儿显存。每轮批量跑前确保 ComfyUI 干净（必要时重启）；若失败任务堆积卡死，请用户在 ComfyUI 面板 Queue → Clear 手动清理。
  - `free_vram()` 调 `POST /free`（body 带 `{"unload_models": true}`，退化为 `/api/free`）做段间 best-effort 卸载；它**不回收失败任务的孤儿显存**。`--disable-smart-memory` 启动参数让每段结束自动卸载，但同样救不了已泄漏的孤儿显存——那种情况只能重启 ComfyUI。

调用：
```bash
python 生成视频.py --config "D:/.../工作配置.yaml"                      # 全段 0.1 抽卡
python 生成视频.py --config "D:/.../工作配置.yaml" --mp 0.6 --only 段2  # 段2 成品档复用抽卡种子
```

## 十、mp / seed 铁律速查

- **mp（种子单一概念，用户定义）**：`mp <= 0.2` = 抽卡档（不传 `--seed`，脚本随机落种并回写 `视频抽卡种子`）；`mp >= 0.3` = 成品档（**必须** `--seed` 传该段抽卡档生成的那个随机数，内容一致只提清晰度，**绝不重新随机**）。多段批量时每段保留自己的段内 `视频抽卡种子` 副本，成品档精准复用本段值、不串段。
- **seed 回写**：随机抽卡的 seed 必须回写 `提示词生成.md` 顶部 `视频抽卡种子`，否则下次 0.3+ 档无种子可复用。
- **help 文案**：py 内 `--seed` 说明已是「0.3-0.9」，与规则一致。

## 十二、校验项目.py（只读一致性校验 · 把"人工自检"固化成一条命令）

> **何时用**：任意阶段跑——初始化后、分镜后、出图后、出视频后，把分散在 `分镜规则.md` / `分镜转视频.md` / `首尾帧生成规则.md` / `初始化文档.md` / `图片重命名规范.md` 的「自检清单 / 红线 / 防漏写 / 铁律 / R1 路由」一次性自动核对，替代每次人肉读文档逐条检查（漏看就出岔子：world书没生成、视频没进工程目录、回写字段名写错、路由选反、seed 串段…）。
> **它只读不写**：不连 ComfyUI、不出图、不修改任何 md / 配置 / 产物。产出 PASS / WARN / FAIL 报告，可 `--report` 落盘 markdown。

### 12.1 参数

| 参数 | 必填 | 含义 |
|---|---|---|
| `--config <工作配置.yaml>` | **必传** | 定位一切（配置 + 一览表 + 提示词生成.md + 磁盘产物） |
| `--check` | 可选 | 只跑指定层：`init` / `assets` / `storyboard` / `frames` / `video` / `all`（默认 `all`） |
| `--only` | 可选 | 段级校验层（storyboard/frames/video）只校验指定段，逗号分隔，如 `段1,段2` |
| `--report <path>` | 可选 | 把报告写成 markdown（含 PASS/WARN/FAIL 表格） |
| `--strict` | 可选 | WARN 也计为失败（退出码 1）；默认仅 FAIL 计失败 |

### 12.2 各层校验内容（对照文档）

| 层 | 校验项（来源） |
|---|---|
| `init` | 配置 8 中文字段齐全；指向的文件（一览表/剧情/提示词/世界书）存在；图片/视频输出目录已建（初始化文档.md） |
| `assets` | 一览表三章节（现有资源角色清单/背景清单/剧情角色清单）齐全；剧情角色清单为 **5 列**；现有/背景/剧情清单非空警告；每条剧情角色「匹配资源角色（参考图）」文件真实存在（func5/6 路由硬依赖，图片重命名规范.md + 分镜转视频 §四） |
| `storyboard` | 顶部 `视频抽卡种子` 存在；每段：视频时长 ≤ 14（硬上限）；`场景背景图`/`场景背景描述` 二选一；`是否生成首帧图片=是` ↔ `生成图片的工作流=图片工作流`、`=否` 不能选 FL2VA；`使用角色` 取自剧情角色清单；**R1 路由一致**（出镜 >2 必 Ref2VA）；`生成视频的提示词` 非空且 FL2VA 含 `Picture 1 (start)`/`Picture 2 (end)`、Ref2VA 含六段式；提示词含「字幕」要求（分镜转视频 §8.2）；无对白段含「全程无人物发声」（分镜规则.md schema / R1 / 分镜转视频 §八） |
| `frames` | func5 回写四字段（场景背景图/背景图片存放位置/生成图片首帧地址/生成图片尾帧地址）非空且文件存在；首帧=否 段不应有残留帧地址（首尾帧生成规则.md 自检） |
| `video` | func6/7 回写 `生成视频地址` 非空且文件存在；段内 `视频抽卡种子` 已固化（mp>=0.3 复用防串段，分镜转视频.md §五 / 调用规范.md §7.1/§十） |

### 12.3 退出码

- 有 `FAIL` → 退出码 `1`（CI / 批处理可作断言行）；
- `--strict` 时，有 `WARN` 也 → `1`；
- 否则 `0`。

### 12.4 调用示例

```bash
# 全量校验（推荐放在每个功能跑完之后）
python 校验项目.py --config "D:/proj/工作配置.yaml"

# 只校验分镜段 schema（不查磁盘产物）
python 校验项目.py --config "D:/proj/工作配置.yaml" --check storyboard

# 只查 func6/7 回写是否落盘 + 段内 seed 固化，仅段1/段2
python 校验项目.py --config "D:/proj/工作配置.yaml" --check video --only 段1,段2

# 出报告 + 严格模式（WARN 也判失败，适合作为交付前门禁）
python 校验项目.py --config "D:/proj/工作配置.yaml" --report 校验报告.md --strict
```

> ⚠️ 本脚本**不修文件**——它只报问题。若要把「字幕要求缺失 / 路由选反 / 回写漏填」等修掉，仍按对应功能脚本或人工改 md；后续若需要可加 `--fix` 自动注入（会改 md，默认不开启，遵从「不擅自改项目文件」红线）。
