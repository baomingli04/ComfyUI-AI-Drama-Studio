# 分镜转视频（参考文档）

> 本文件定义 **功能 6（全量分镜 → 视频）** 与 **功能 7（指定分镜 → 视频，含自定义 mp）**。  
> 两个功能共用同一套「读 md → 路由 → 调 py → 回写」逻辑，差异仅在：功能 7 只处理用户指定的段、并按用户给的 mp 覆盖分辨率。

## 何时读 / 读它干什么 / 不读会漏什么

- **何时读**：功能 6 / 7 调用时——已拿到 `提示词生成.md` 分镜与功能 5 的首尾帧图，要逐段生成视频。
- **读它干什么**：按本规范把每段分镜路由到正确视频工作流（FL2VA / Ref2VA），接好首帧（尾帧可选）/ 参考图 / 时长 / 提示词 / 分辨率，产出成片并回写地址。
- **不读会漏什么**：工作流选错、FL2VA 段没接首尾帧、Ref2VA 的 `--images` 顺序错（背景没放最后 → 串脸）、视频时长超 14 秒、mp 擅自改值、成片地址漏回写 → 成片错乱或后续对不上。

---

## 一写了一些py、总流程

```
读 工作配置.yaml（取 提示词生成文件 / 视频输出目录 / 角色背景一览表 路径）
  │
  ├─ 解析 提示词生成.md 所有 「## 段<N>」块
  │
  ├─ 逐段按「生成视频的工作流」字段路由：
  │     ├─ "视频-首尾帧"  → 走 FL2VA 路径（见 二）
  │     └─ "视频-多参考"  → 走 Ref2VA 路径（见 三）
  │
  ├─ 每段调对应 py 脚本生成视频（功能 7 只跑用户指定的段）
  │
  └─ 每段把成片绝对路径回写到 提示词生成.md 的「生成视频地址」字段
```

| --------------- | ------------ | ---------------------------------------------------------------------- |

## 三、路由 A：视频-首尾帧（FL2VA）→ `FL2VA首尾帧视频.py`

**前提**：本段 `是否生成首帧图片 = 是` 且 `生成图片首帧地址` 已存在（功能 5 产出）。`生成图片尾帧地址` **可选**：缺省时视频步自动复用首帧为尾帧（首帧-only 模式，功能 5 默认只出首帧时的标准用法）。

### 传参映射

| 脚本参数                  | 来源                                                         | 备注                          |
| --------------------- | ---------------------------------------------------------- | --------------------------- |
| `--first-dir DIR`     | 本段 `生成图片首帧地址` 所在目录（或把该帧放入一个目录）                             | 详见下方「批量 vs 逐段」              |
| `--last-dir DIR`      | 本段 `生成图片尾帧地址` 所在目录（**可选**）                                   | 不传 → 首帧-only：底层复用首帧为尾帧        |
| `--prompts-file FILE` | 本段 `生成视频的提示词`（FL2VA 单行）写入一个 txt，每行一段                       | 逐段调用时该文件仅 1 行               |
| `--megapixels MP`     | **用户指令**（见 §五 mp 铁律）                                       | 抽卡默认 0.1；用户指定则透传            |
| `--duration SEC`      | `视频时长` 数值秒                                                 | ≤14；不传则工作流默认分支（无对白5s/有对白8s） |
| `--aspect RATIO`      | 默认 `9:16`（竖屏短视频）                                           | 横屏用 `16:9`                  |
| `--output-prefix`     | 建议含段号，如 `video/MiniMax_H3_段1`                              | 防互顶 + 便于 `locate_video` 定位  |
| `--comfy-output DIR`  | ComfyUI output 根（如 `D:/ComfyUI-aki-v3/ComfyUI/output`）     | 必传，用于防互顶 + 定位成片             |
| `--comfy-url`         | 默认 `http://127.0.0.1:8188`；远程 `http://192.168.31.131:8488` | 按需覆盖                        |
| `--seed`              | 可选；不传＝随机抽卡（脚本打印 seed），传＝固定复用成品                             | 抽卡记 seed，成品 `--seed` 复用     |

### 批量 vs 逐段（两种调用方式，任选）

- **批量（推荐，省 ComfyUI 调用）**：把所有 FL2VA 段的**首帧**按段序放进一个目录（`001.png`=段1首帧、`002.png`=段2首帧…），**尾帧**同理（尾帧目录可省略，省略则首帧-only，底层自动复用首帧为尾帧）；把所有段的 FL2VA 提示词按同序写入一个 txt（每行一段）。一次 `FL2VA首尾帧视频.py --first-dir ... [--last-dir ...] --prompts-file ...` 跑完所有 FL2VA 段。成片按循环顺序产出，**第 i 个产出 = 第 i 个 FL2VA 段**，据此写回各段 `生成视频地址`。
- **逐段**：每段单独建首/尾帧目录（仅含该段一对帧）与单行星提示词文件，调用一次。回报是每段一个成片、写回 1:1 无歧义、且可逐段设不同 `--duration`（批量只能统一时长）。段时长不一致时优先逐段。

### 帧目录桥接（功能 5 → FL2VA 必做）

功能 5 把首/尾帧落在 `图片输出目录`，命名为 `<段N>_首帧.png` / `<段N>_尾帧.png`（见 `首尾帧生成规则.md` 落盘命名）；但 FL2VA 工作流按「目录 + 顺序」读帧——`--first-dir` / `--last-dir` 目录内 `001.png`=段1首帧、`002.png`=段2首帧…。**两者命名规范不同，功能 5 产出不能直接喂给 FL2VA，必须做桥接：**

- **批量（推荐，省 ComfyUI 调用）**：把所有 FL2VA 段的「首帧」按段序重命名为 `001.png`、`002.png`… 放进一个首帧目录；「尾帧」同理放进尾帧目录（尾帧目录可省略：省略则首帧-only，底层复用首帧为尾帧），一次 `--first-dir … [--last-dir …]` 跑完所有段。
  - 即从 `图片输出目录` 取 `段1_首帧.png`→`首帧目录/001.png`、`段2_首帧.png`→`首帧目录/002.png`…；尾帧目录同法。
- **逐段**：每段单独建 `段N_首帧_dir`（内含该段首帧 png，文件名任意）/ `段N_尾帧_dir`，调用一次 `--first-dir 段N_首帧_dir --last-dir 段N_尾帧_dir`。回报：每段一个成片、写回 1:1 无歧义、可逐段设不同 `--duration`（批量只能统一时长）。

> 命名提示：FL2VA 只按目录内 PNG 排序取第 i 张，文件名本身无所谓；批量务必保持「段序 = 数字序」，否则首尾帧错位。

### 首帧-only 模式（功能 5 默认只出首帧时的标准用法）

功能 5（`生成首尾帧与背景.py`）现已默认只出**首帧**（`--frames first`），尾帧不再生成。因此 FL2VA 视频步的默认形态是**首帧-only**：

- `FL2VA首尾帧视频.py` 的 `--last-dir` 改为**可选**。不传时，脚本自动把首帧目录里的图复制一份作为尾帧，喂给现有 MiniMax H3 FL2VA 工作流——即**唯一源图就是首帧**，视频仅由首帧驱动（模型节点仍是 `task_type: FL2VA`，首尾帧输入同源）。
- `生成视频.py` 新增 `--frames` 参数（默认 `first`），与功能 5 的 `--frames` 完全对齐：`--frames first` 时**无视尾帧、永远首帧-only**；`--frames both` 且尾帧存在时才传 `--last-dir` 走首+尾。因此默认跑视频就是首帧-only，无需尾帧。
- 若功能 5 显式用了 `--frames both` 出过尾帧、且 `生成图片尾帧地址` 已填，则照旧传 `--last-dir`（首+尾双图）。
- 文档与脚本已同步：尾帧由「必填」降级为「可选」。

> 注意：首帧-only 下视频起止画面同源（尾帧=首帧），短片会自然回到起始姿态，属可接受范围。若后续需要真正的「单图生视频（I2VA，无尾帧输入）」质量，需改工作流节点 `211` 的 `task_type` 为 `I2VA` 并断开 `last_frame`，属工作流层改动，不在本次 py/doc 范围内。

> FL2VA 不消费 `使用角色` / `场景背景图` / `Ref2VA资源分配`——起止画面已由首尾帧图锁定。

> **视频提示词的角色指代（FL2VA 特有）**：首尾帧只喂入起止帧画面、无角色参考图，模型只认画面、不认人名。多人段一律用「左侧人物 / 右侧人物 / 上方人物」等**位置指代**，不要写「鸣人 / 佐助」等人名（规则见 `分镜规则.md §2`）；单人段可省略指代。

## 四、路由 B：视频-多参考（Ref2VA）→ `Ref2VA多参考视频.py`

**前提**：本段 `是否生成首帧图片 = 否`（人物 > 2 / 无首帧人物 / 走多参考不单独出首帧）。

### 传参映射

| 脚本参数                                        | 来源                               | 备注                                                        |
| ------------------------------------------- | -------------------------------- | --------------------------------------------------------- |
| `--images IMG1..IMGN`                       | **角色参考图（按 `使用角色` 顺序）+ 背景图放最后一张** | 顺序 = ref_image_0..N-1；**背景图必须末张**（防串脸，见 `分镜规则.md › 3` 铁律） |
| `--prompt TEXT`                             | 本段 `生成视频的提示词`（六段式）               | 原样透传；正文用 `<Subject N>`、禁中文名                               |
| `--megapixels MP`                           | **用户指令**（见 §五）                   | 不传则随 preset（`opt`=0.3 / `v5`=0.4）；或 `--preset opt/v5`     |
| `--duration SEC`                            | `视频时长` 数值秒                       | ≤14                                                       |
| `--aspect`                                  | 默认 `9:16`                        |                                                           |
| `--videos` / `--audios`                     | 可选，0~3 个参考视频 / 音频                | 取自带视频 / 音频资产；不传不接                                         |
| `--output-prefix`                           | 建议含段号，如 `video/MiniMax_H3_段3`    |                                                           |
| `--comfy-output` / `--comfy-url` / `--seed` | 同 FL2VA                          |                                                           |

### `--images` 组装规则（关键，错序会串脸）

1. 解析本段 `使用角色`：每行 `图片N: 角色名` → 按 N 顺序得到角色名列表。
2. 查 `角色背景一览表.md` 的「剧情角色清单」：角色名 → 匹配资源角色（参考图文件名）→ 得到**角色参考图绝对路径**列表。
3. 追加 `场景背景图`（已存在背景文件名，解析为绝对路径）作为**最后一张**。
4. 拼成 `--images 角色1图 角色2图 … 背景图`。

> 例：段 `使用角色` = `图片1: 鸣人` / `图片2: 佐助`，`场景背景图` = `木叶村口大道_背景.png`  
> → `--images char_naruto.png char_sasuke.png 木叶村口大道_背景.png`  
> （`char_naruto.png` / `char_sasuke.png` 由一览表解析；背景末张 = Picture 3，对应六段式里 `<Subject 场景> 来自 <Picture 3>`）

> Ref2VA 不消费 `生成图片首帧地址` / `生成图片尾帧地址`（多参考不走首尾帧）；也不要求 `是否生成首帧图片 = 是`。

> **视频提示词的角色指代（Ref2VA 特有，MiniMax 官方 reference-to-video 规则）**：每张 `--images` 传入的参考图必须在提示词里按序号「指派任务」（如「图片1 是主角A 参考、图片2 是主角B 参考、图片3 是背景」），并写明每个输出角色在画面中的位置（按 `<Subject N>`：左 / 右 / 前 / 后 / 上 / 下）。不指派任务模型会猜错谁是谁、易串脸；不写位置会居中漂移。详见 `分镜规则.md §3`。

## 五、分辨率（mp）铁律 —— 全看用户说的算

`megapixels`（百万像素，简称 mp）**完全由用户当轮指令决定**，脚本 `--megapixels` 一律透传，**绝不擅自改值**。

- **抽卡（draft）阶段**：用户未定稿时默认 **0.1**。`FL2VA首尾帧视频.py` 内置兜底即 0.1；Ref2VA 不传 `--megapixels` 时回落 preset（`opt`=0.3 / `v5`=0.4），**要抽卡 0.1 必须显式 `--megapixels 0.1`**。
- **用户说「用 0.几 mp」** → 一律按 **0.1**（抽卡草稿），不自动上调。
- **成品（final）阶段**：用户指定 `0.3` / `0.4` 等 → `--megapixels` 传该值（Ref2VA 也可用 `--preset opt`=0.3/11s 或 `v5`=0.4/5s，或直接 `--megapixels` 覆盖 preset）。
- **任何取值以用户明确指令为准**：文档/脚本默认值仅在用户未指定时启用；用户给了具体 mp，脚本只负责原样透传。

### 5.2 抽卡 seed 复用铁律（0.1 / 0.2 随机 → > 0.2 复用）

出视频的 `--seed` 与 mp **强绑定**，目的是让 0.3/0.4 成品和 0.1/0.2 抽卡「是同一张脸、同一套构图」，可直接放大定稿、不至于换人换景：

- **mp = 0.1 / 0.2（抽卡草稿）**：`--seed` **不传**（脚本随机抽卡）。每段成片后，把本次随机 seed **回写**到 `提示词生成.md` 顶部全局字段 `视频抽卡种子`（见 `分镜规则.md` schema 顶部字段）。
- **mp > 0.2（0.3 ~ 0.9 成品）**：`--seed` **必须读取**顶部 `视频抽卡种子` 字段、原样复用该值（= 0.1/0.2 最后一次抽卡的 seed），**绝不重新随机**。成品仅分辨率更高，人物 / 构图与抽卡一致。
- **回写实现**：py 跑完 0.1/0.2 视频打印 `SEED: <num>`，并由 `项目路径.write_back_top_field` 写回 `提示词生成.md` 顶部 `视频抽卡种子`（幂等覆盖，永远是最后一次抽卡值）。
- **校验**：自检项增加「> 0.2 MP 段是否读取并复用了顶部 `视频抽卡种子`，未擅自随机」。

> 一句话：**0.1/0.2 抽卡要落 seed 到文档顶部；0.3+ 一律吃这个 seed，不许自己抽。**

## 六、回写字段映射

每段生成后，脚本会打印 `FINAL_VIDEO: <绝对路径>`。用 `项目路径.write_back_field` 回写：

```python
import 项目路径 as pp
pp.write_back_field(提示词生成.md路径, "段<N>", "生成视频地址", final_video_path)
```

- `生成视频地址` 字段在 schema 中已存在 → 幂等覆盖占位（反复跑不重复插入）。
- 批量 FL2VA：跑完按循环顺序把第 i 个成片写回第 i 个 FL2VA 段的 `生成视频地址`。
- FL2VA 的 `locate_video` 依赖 `--comfy-output` 指向真实 ComfyUI output 根；**务必显式传**，否则定位不到成片。

## 七、官方执行器（生成视频.py）

上文 §三/§四/§五/§六 的「读 md → 路由 → 帧目录桥接 / `--images` 组装 → 调 py → 回写」全部由官方执行器 **`py脚本/生成视频.py`** 封装，无需手搓驱动。它是功能 6/7 的**唯一推荐入口**。

职责（与本文一一对应）：
- 按每段的 `生成视频的工作流` 路由：视频-首尾帧 → FL2VA（先做 §三 帧目录桥接）、视频-多参考 → Ref2VA（按 §四 `--images` 组装，背景末张）。
- 种子铁律（§五 5.2）：`--mp <= 0.2` 不传 `--seed`（底层随机并回写顶部）；`--mp >= 0.3` 读该段【段内】`视频抽卡种子` 传 `--seed` 复用，绝不重新随机。每段跑完把顶部值**按段固化**到段内，防批量多段互相覆盖。
- 回写（§六）：成片 `FINAL_VIDEO` 写回该段 `生成视频地址`。

调用：
```bash
# 全段 0.1 抽卡（随机落种 + 段内固化）
python 生成视频.py --config "D:/proj/工作配置.yaml"

# 指定段 成品档（>=0.3 复用该段抽卡种子）
python 生成视频.py --config "D:/proj/工作配置.yaml" --mp 0.6 --only 段2
```

> ⚠️ **失败直接跳下一段（用户硬规则，func5 / func6 / func7 统一适用）**：单个任务在代码层（出图 / 出视频子脚本）失败时，执行器**不取消 ComfyUI 任务、不清理队列**，直接跳过本段、`continue` 后续段；等待时间**无限**（`Comfy客户端.wait` 不超时，只有 ComfyUI 工作流执行报错才抛出）。
> - **功能 5（生成首尾帧与背景.py）**：单段出图异常 → 仅打印错误 + 跳过本段 + `continue` 后续段，**不再**调用 `cancel_comfyui`；进程退出 / 中断**不**清理 ComfyUI 队列，仅释放运行锁。
> - **功能 6/7（生成视频.py）**：每段独立视频，单段失败 → 仅打印错误 + 跳过本段 + `continue` 后续段，不取消 ComfyUI 任务。
> - 共同前提：批量跑前确保 ComfyUI 干净（必要时重启），因为 ComfyUI 不会自动回收失败 / 中断任务泄漏的孤儿显存；若失败任务堆积卡死，请用户在 ComfyUI 面板 `Queue → Clear` 手动清理。

> ⚠️ **显存管理（实测踩坑，记准）**：ComfyUI **不会自动回收「中断 / 失败任务」占用的显存**。调试期若反复提交会失败的任务，孤儿显存会不断累积；跑到后段时显存被占满 → 权重落 CPU → 报
> `Input type (torch.cuda.FloatTensor) and weight type (torch.FloatTensor) should be the same`（CUDA 类型不匹配 / OOM）。
> **真因不是「段间没清显存」**，而是运行被失败 / 中断任务污染——孤儿显存只能靠**重启 ComfyUI** 清除（重启后正常跑通，已验证）。`Comfy客户端.free_vram()` 仅做段间 best-effort 卸载，**无法回收失败任务泄漏的孤儿显存**，别把它当「防 CUDA 报错」的银弹。
>
> **实操建议**：每轮批量跑之前确保 ComfyUI 是干净状态（必要时重启），单段底层脚本失败时执行器会 `interrupt`+清队列（见上条）避免失败任务堆积泄漏显存。正常成功跑完的一轮，段间无需特殊处理。

## 九、声音与字幕规范（功能 6/7 必须遵守）

### 8.1 声音口径（与《需求转情节》红线 6 一致）

视频成片的声音从严：**不主动加 BGM、不主动加环境声，只留人物说话声 + 极必要时关键动作声**。

- **人物说话声（默认必备）**：角色台词写在分镜「对话」栏，由音频配置阶段按「角色名 → 音色文件」合成配音，成片自然带说话声；对话段必须有清晰中文配音（除非用户明确要静音）。
- **禁止 BGM**：任何段落都不要主动加背景音乐。
- **禁止环境声**：不要主动加自然环境声（风声 / 雨声 / 海浪 / 虫鸣）与环境人声底噪（嘈杂 / 低语 / 喊声 / 教室杂音）。
- **关键动作声（仅必要时）**：确有必要时，才在提示词里写与可见动作直接对应的关键动作声（武器挥击 / 拳脚击打 / 摔落 / 衣料摩擦），且仅此一种非台词声；非必要时留空，不靠声音补音量。

> 声音最终由「音频配置阶段（配音）」与「视频模型提示词（动作声）」共同落实，不在视频脚本的 `--megapixels` 等参数里；脚本无需也不接受声音参数。

### 8.2 中文字幕（必须）

成片**必须生成中文字幕**。MiniMax H3 视频模型自带中文字幕能力，**在每段 `生成视频的提示词` 末尾明确写入「生成中文字幕」要求即可启用**（如 FL2VA 单行 / Ref2VA 六段式正文末尾加 `生成中文字幕`）。

- 对话段：字幕内容 = 该段「对话」栏中文台词；由模型生成对齐口型的硬字幕。
- 无对话段：不强行加字幕（纯动作 / soundscape 段无字幕），避免空字幕穿帮。
- 字幕语言固定中文；禁止英文 / 拼音字幕。

> 字幕指令只写进 `生成视频的提示词` 正文（FL2VA / Ref2VA 各自提示词格式见 `分镜规则.md`），由视频模型消费；脚本透传提示词，不单独处理字幕参数。
