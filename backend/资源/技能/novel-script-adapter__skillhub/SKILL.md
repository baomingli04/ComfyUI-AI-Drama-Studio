# 短剧剧本创作 Skill

## 工作总流程

```
模式判断 → 输入处理 → 结构设计 → 产物生成 → 质量校验 → 交付
```

### 第零步：模式判断

根据用户输入自动判断使用哪种模式：

| 用户输入 | 模式 |
|---------|------|
| 上传小说文件 / 提供小说文本 / 明确说"改编" | 模式A或B（小说改编） |
| 描述想法/需求 / 说"写一个短剧" / "原创" / "新写一个剧本" | 模式C（原创短剧） |
| 同时提到小说和原创想法 | 询问用户意图后确定 |

**判断原则**：不主动追问模式，根据用户输入自动判断；只有当用户意图确实模糊时才询问。

### 第一步：接收与预处理小说

1. 接收用户上传的小说文件（支持 .txt / .docx / .pdf / .md 等任意文本格式）
2. 若文件过大，分段读取，确保全文覆盖无遗漏
3. 识别章节结构，建立章节索引
4. 统计基本信息：总字数、章节数、主要人物数量

### 第二步：小说深度解析

**必须完整解析以下所有维度，不可遗漏：**

| 解析维度 | 核心内容 | 参考文件 |
|---------|---------|---------|
| 人物体系 | 主角/核心配角人设、人物关系网、成长弧线、口头禅与语言风格 | [novel-analysis-framework.md](references/novel-analysis-framework.md) |
| 剧情脉络 | 主线/支线/暗线、起承转合结构、关键转折点、伏笔与回收 | [novel-analysis-framework.md](references/novel-analysis-framework.md) |
| 名场面 | 高燃/高虐/名台词场景、标志性事件、读者记忆点 | [novel-analysis-framework.md](references/novel-analysis-framework.md) |
| 世界观 | 时代背景、地理设定、势力划分、规则体系、特殊设定 | [novel-analysis-framework.md](references/novel-analysis-framework.md) |
| 时间线 | 故事时间跨度、关键时间节点、事件先后顺序 | [novel-analysis-framework.md](references/novel-analysis-framework.md) |
| 主题内核 | 核心主题、情感基调、价值观表达 | [novel-analysis-framework.md](references/novel-analysis-framework.md) |

> **重要**：解析完成后，先向用户输出「小说解析摘要」确认，确认无误后再进入改编阶段。

### 第三步：改编模式选择

根据用户需求选择以下两种模式之一：

#### 模式A：忠实原著改编
- **核心原则**：原封不动按小说故事线生成剧本
- **台词规则**：严格遵守原著台词，一字不改，除非用户明确要求调整
- **剧情规则**：完全遵循原著叙事顺序与情节
- **适用场景**：粉丝向改编、经典IP还原、用户明确要求"不改原著"

#### 模式B：优化改编
- **三不变原则**：
  1. 主角及核心配角人设不变
  2. 剧情完整脉络不变
  3. 重点名场面不变
- **可优化范围**：
  - 节奏调整（压缩冗余、强化冲突）
  - 叙事顺序优化（插叙/倒叙运用）
  - 支线整合与精简
  - 视觉化增强（增加画面感）
  - 对话口语化适配（不改变原意）
  - **短剧爽感强化**（打脸反转、冲突密度、爽点前置、钩子设计）
  - **配角台词人设化**（每个配角必须有鲜明的语言标签和说话方式，用冲突式对话代替说明式对话，具体规则见下方）
  - **AI漫剧分镜提示词**（每个镜头附带可直接用于AI生图/生视频的提示词，含角色锁定词、场景锚定、运镜参数，适配即梦/可灵/Runway等平台）
- **适用场景**：商业改编、短视频平台适配、载体转换优化、AI漫剧制作

#### 配角台词人设化规则（v1.3.0增强）

**核心原则：每个配角开口前，先给他贴一个"语言标签"，让观众听台词就知道是谁在说话。**

**1. 语言标签设计**
- 每个核心配角必须有独特的说话方式，从以下维度选择1-2个：
  - 口头禅（如"不是我说啊""你懂我意思吧"）
  - 句式偏好（短句连珠/反问句/文绉绉/大白话）
  - 语气特征（阴阳怪气/谄媚/嚣张/怯懦/官腔）
  - 身份烙印（商人谈利/军人下命令/长辈说教/混混放狠话）

**2. 冲突式对话三原则**
- **不说"正确的废话"**：配角不要替作者解释剧情，所有信息通过冲突传递
  - 错误："这个项目价值三个亿，对公司很重要"
  - 正确："三个亿的项目，你张昊一句话就想吞了？"
- **每句对话都要有潜台词**：表面说A，实际意思是B
  - "林总好久不见"（潜台词：你不是被赶走了吗怎么回来了）
  - "您大人有大量"（潜台词：你别跟我计较/我害怕了）
- **对话即动作**：每句对话都在推进关系或制造冲突
  - 上位者：打断、命令、反问
  - 下位者：试探、辩解、讨好
  - 敌对者：嘲讽、威胁、揭短

**3. 反派台词要点**
- 反派不能"坏得直白"，要有自己的逻辑和立场
- 嚣张时给具体细节（"你爸住院那天，是我签的字"）
- 被打脸时先不信→强撑→崩溃，三层递进
- 反派的跟班负责"捧哏"和"递刀"，替反派说观众想听的狠话

**4. 配角对话示例对比**

| 说明式（生硬） | 冲突式（人设化） |
|---|---|
| "张总，林寒回来了，他现在持有42%股份" | "张、张总！林寒他……他带着股权书回来了！42%！" |
| "你被逐出公司三年，早就不是林氏的人了" | "三年前你像条狗一样被赶出去，现在穿身西装就想回来？" |
| "各位董事，这是张昊挪用公款的证据" | "各位看好了——张昊这三年转走的每一笔钱，都在这儿。" |

> **集数与风格**：三种模式均根据用户指定的集数和剧情风格进行适配。

#### 模式C：原创短剧模式（v1.5.0新增）

**核心原则**：用户只需要有一个想法，AI通过智能澄清后从零原创完整剧本，不需要任何原著文本。

**C-1：需求接收与智能澄清**

接收用户的初始想法后，根据需求明确程度智能决定追问内容，**不要一次性抛出所有问题**：

| 用户输入明确程度 | 判断标准 | 追问策略 |
|---|---|---|
| 模糊 | 只有"帮我写个短剧"或类似泛泛描述 | 依次问：①题材类型（都市/古装/悬疑/甜宠/逆袭等）②核心主题或爽点 ③目标集数 ④风格调性 |
| 较明确 | 给了题材或主题，但没给集数 | 只问：①目标集数 ②每集时长偏好（可选） |
| 非常明确 | 题材+主题+集数都给了 | 不再追问，直接确认需求后开始创作 |

**追问示例**：
- 用户："帮我写个短剧" → "好的！你想做什么题材？比如都市逆袭、古装甜宠、悬疑反转、重生复仇等"
- 用户："写一个都市逆袭爽剧" → "没问题，计划做多少集？每集1-2分钟的竖屏短剧吗？"
- 用户："写一个10集都市逆袭爽剧，主角被陷害后王者归来" → 直接确认需求摘要，开始创作

**C-2：需求确认**

澄清完成后，输出「原创需求摘要」让用户确认：

```
【原创需求摘要】
题材：XXX
核心主题/爽点：XXX
集数：XX集
每集时长：XX秒
目标平台：抖音/快手/视频号
风格调性：XXX
主角设定方向：XXX
```

用户确认后进入创作。用户修改需求时，按修改后的版本执行。

**C-3：原创大纲设计**

从零构建以下内容（无原著参考，完全原创）：

| 设计维度 | 要求 |
|---------|------|
| 核心创意 | 一句话Logline + 核心卖点 + 差异化定位 |
| 人物体系 | 主角人设（姓名/性格/背景/成长弧线/口头禅）、核心配角2-4人（每人配语言标签）、反派设定 |
| 世界观 | 时代背景、场景设定、特殊规则（如有） |
| 主线脉络 | 起承转合结构、核心冲突、关键转折点、伏笔设计 |
| 爽点/钩子分布 | 每集的核心爽点/情绪点规划，确保节奏递进 |
| 结局设计 | 大结局方向、情感落点、是否留续集空间 |

大纲完成后先向用户输出确认，确认后进入分集剧本。

**C-4：原创模式的特殊要求**

- 人设必须原创且鲜明，避免脸谱化，主角要有明确的欲望和缺陷
- 前三集必须完成"主角困境→触发事件→第一次反转"的完整钩子链
- 每集的爽点/反转不能重复，要有递进升级
- 配角台词同样遵循下方"配角台词人设化规则"
- 可以融入当下热门元素但不能抄袭已有作品
- 如果用户后续提供了参考作品或小说，可切换到模式A/B

### 第四步：每集结构设计（核心强制规则）

**每一集剧本，无论模式A还是模式B，都必须严格按照以下三段式结构生成，钩子和悬念直接写入剧本中，不单独列出让创作者自己添加：**

#### 三段式结构公式

```
┌─────────────────────────────────────────────┐
│  3秒钩子开场（Hook）                          │
│  → 名场面主体（Body）                         │
│  → 结尾悬念/反转（Cliffhanger）               │
└─────────────────────────────────────────────┘
```

**第一段：3秒钩子开场（前3秒/前1-2个镜头）**
- 必须在每集最开头3秒内抓住观众，以下任选一种：
  - 冲突前置：把本集最激烈的冲突/打脸瞬间放到开头（"你被开除了""我们离婚吧"）
  - 结果前置：先展示结局画面再闪回（"这是他最后悔的一天"）
  - 视觉冲击：强烈的画面（摔文件、下跪、暴雨中嘶吼）
  - 反常识陈述：一句颠覆认知的台词
  - 直接提问：与剧情相关的悬念问题
- 钩子必须直接写在剧本第一行，不是备注、不是建议，是剧本的组成部分
- 钩子内容必须与本集主体相关，不能做标题党

**第二段：名场面主体（本集核心内容）**
- 每集必须包含至少1个原著名场面（模式A）或优化后的名场面（模式B）
- 名场面是本集的情绪高点和传播点，必须给足篇幅和细节
- 短剧每集至少安排1-2个爽点（打脸反转/身份揭露/实力碾压/恶人遭报）
- 主体部分按场景推进，节奏紧凑，删除无意义的过场和铺垫
- 对白口语化、精炼，符合短剧快节奏特点
- 场景转换简洁，控制场景数量，降低制作成本

**第三段：结尾悬念/反转（最后5-10秒/最后1-2个镜头）**
- 每集结尾必须留钩子，让观众想看下一集，以下任选一种：
  - 悬念式：关键信息只露一半（"他到底是谁？""真相竟然是……"）
  - 反转型：最后一秒推翻本集认知（以为赢了其实中了圈套）
  - 危机式：新的威胁出现（门被推开、电话响起、人物倒地）
  - 情感式：关系突变（表白/背叛/离别/重逢）
- 悬念必须直接写在剧本最后，作为本集最后一个镜头/最后一句台词
- 结尾悬念要与下一集开头自然衔接

#### 时长规则

**如果用户没有明确指定每集时长，必须根据体裁和集数给出精准时长建议（只给一个数字，不给区间）：**

| 体裁 | 集数 | 建议每集时长 |
|---|---|---|
| 抖音/快手短剧 | 10集以内 | 90秒 |
| 抖音/快手短剧 | 10-30集 | 120秒 |
| 抖音/快手短剧 | 30集以上 | 150秒 |
| 小红书/视频号短剧 | 不限 | 180秒 |
| B站短剧/漫剧 | 不限 | 300秒 |
| AI漫剧（竖屏） | 不限 | 120秒 |
| AI漫剧（横屏） | 不限 | 180秒 |

- 用户有时长要求时，严格按用户要求的时长
- 用户没有要求时，从上表选择对应时长，直接告诉用户"建议每集XX秒"，不要给区间
- 剧本中每个镜头/场景的时长之和必须等于建议时长

### 第五步：产物生成

根据需求生成以下全部或部分产物：

| 产物 | 内容说明 | 模板 |
|-----|---------|-----|
| **原始创意** | 核心概念、卖点提炼、目标受众、差异化定位 | [script-template.md](assets/script-template.md) |
| **剧本大纲** | 整体故事结构、主线走向、关键节点、每集三段式梗概（钩子+名场面+悬念） | [script-template.md](assets/script-template.md) |
| **剧本摘要** | 一句话简介、三百字梗概、千字详梗 | [script-template.md](assets/script-template.md) |
| **分集剧本** | 每集完整剧本（含3秒钩子开场+名场面主体+结尾悬念，场景+动作+对话+旁白+时长） | [script-template.md](assets/script-template.md) |
| **AI漫剧分镜提示词** | 每个镜头附带可直接用于AI生图/生视频的完整提示词，含角色锁定词、场景锚定、运镜参数、画风词、负向词，适配即梦/可灵/Runway等平台 | [script-format-standard.md](references/script-format-standard.md) |

**AI漫剧分镜提示词输出规范（v1.3.0增强）**：

当用户需要AI漫剧分镜提示词时，每个镜头必须输出以下完整字段，创作者复制即可使用，无需二次补充：

```
镜头N：
景别：[特写/近景/中景/全景/远景]
运镜：[推/拉/摇/移/跟/固定]
画面：[人物动作+表情+位置+环境+光线，现在时，可见内容]
台词：[角色名：对话内容]
时长：X秒
转场：[硬切/叠化/淡出]
角色锁定词：[每个角色的固定外貌描述，跨镜头一字不差]
完整提示词（中文，一键复制）：[景别+运镜+角色+动作+表情+环境+光线+画风+画质参数，末尾直接拼接"，排除：变形/模糊/多余手指/低画质/卡通"等负向词]
风格参考描述：[用文字描述该镜头的参考风格，如"参考王家卫电影《花样年华》的暖黄调+慢镜头"，不输出文件路径]
```

**关键要求**：
1. 角色锁定词在所有镜头中一字不差重复，确保角色一致性
2. 提示词必须包含：景别+运镜+角色+动作+表情+环境+光线+画风+画质参数
3. 提示词全部使用中文，正负向合并为一条完整提示词，用户一键复制即可使用（即梦、可灵、Vidu等国内平台均支持中文）
4. 提示词中包含台词内容（支持生成声音的平台会自动配音）
5. 转场效果写入提示词（如"硬切到下一镜""叠化转场"）
6. **极致细致**：每个维度必须具体到可执行的视觉描述，禁止笼统形容词。角色面部要写到脸型/眉形/眼型/鼻型/唇形/肤色/特征标记；光线要写到方向/类型/色温/明暗；动作要写到起止状态；表情要写到具体面部肌肉变化
7. **画风确认**：生成AI漫剧分镜提示词前，必须先确认画面风格（真人写实/日系动漫/国风/赛博朋克等），用户确认后才生成
8. **先确认后输出**：剧本大纲和画风方向必须经用户确认后，才进入分集剧本和分镜提示词生成

**剧本格式标准**：统一使用专业剧本格式，详见 [script-format-standard.md](references/script-format-standard.md)

**改编技巧与方法**：详见 [adaptation-patterns.md](references/adaptation-patterns.md)

### 第六步：质量校验

生成完成后必须执行质量校验，详见 [quality-checklist.md](references/quality-checklist.md)

必检项：
1. 台词保真度检查（模式A必检）
2. 人设一致性检查（三种模式均检）
3. 剧情完整性检查（三种模式均检）
4. 名场面还原度检查（模式A/B必检）
5. 集数与时长匹配校验（三种模式均检）
6. **三段式结构检查**：每集是否有3秒钩子开场、名场面主体、结尾悬念（三部分缺一不可）
7. **钩子有效性检查**：开场3秒是否有足够冲击力
8. **悬念连贯性检查**：每集结尾悬念是否与下一集开头衔接
9. **原创性检查**（模式C必检）：人设、剧情、关键桥段是否有抄袭已有作品的嫌疑，确保原创性
10. **爽点递进检查**（模式C必检）：各集爽点/反转是否有递进升级，不重复

2. 支持单集修改、人设微调、剧情增删等局部迭代

7. **智能追问**：模式C下根据需求明确程度决定追问多少，不一次性抛出所有问题，用户需求明确时不反复追问

## Pay Skill 付费说明（X402 协议）

本 Skill 为按次付费 Skill，通过 X402 协议（HTTP 402 Payment Required）实现授权。

### 前置检查

调用前确认宿主 Agent 支持 X402 协议。若不支持，提示用户升级至支持 Pay Skill 的 Agent 环境。

### 支付触发

1. 按本文档要求整理输入参数，正常调用 Skill 远端接口
2. 若收到 HTTP 402 Payment Required 响应，表示需要付费授权
3. 从 402 响应中读取支付要求（payment requirements），按 X402 协议完成支付授权
4. 支付授权由宿主平台统一处理，Skill 本身不涉及任何支付工具调用

### 重试机制

1. 支付授权完成后，从 402 响应头中获取订单标识（X-Out-Trade-No）
2. 在后续请求头中携带该订单标识重新调用 Skill 接口
3. 服务端验证订单支付状态后返回结果
4. 同一订单号重复请求做幂等处理，只履约一次

### 异常处理

- 用户取消支付：提示可重新发起调用
- 支付凭证过期：重新调用接口获取新的 402 支付挑战
- 支付后重试仍返回 402：等待 3 秒后重试一次，仍失败则提示检查支付状态
- 服务暂时不可用（5xx）：保留订单号，稍后重试
- 订单已使用：提示该订单已完成履约，如需再次使用请重新发起
- 退款：通过 SkillHub 平台统一申请
